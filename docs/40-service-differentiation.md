# CodeTrip 서비스 차별점

## 1. 한 줄 정의

CodeTrip은 여행지를 많이 보여주는 서비스가 아니라, **어디로 갈지부터 막막한 사용자가 자신의 상황에 맞는 여행 선택을 시작하고 계획까지 이어가도록 돕는 여행 의사결정 지원 서비스**입니다.

## 2. 해결하려는 사용자 문제

여행 계획의 첫 단계에서 사용자는 목적지를 정하지 못해 검색조차 시작하기 어려울 수 있습니다. 정보가 많은 서비스는 이미 “가고 싶은 지역”이나 “찾고 싶은 장소”가 있는 사용자에게 유용하지만, 선택 기준이 정리되지 않은 사용자에게는 더 많은 목록이 오히려 부담이 될 수 있습니다.

CodeTrip은 이 문제를 다음 흐름으로 다룹니다.

```text
막연한 여행 의도
  → 날씨·위치·관심 지역을 반영한 탐색 시작
  → 후보 여행지를 찜·폴더로 비교·정리
  → AI 여행 일정 초안 생성
  → 지역의 신규 장소·행사 정보 확인
  → 다음 여행 계획에 다시 활용
```

## 3. 차별점

### 3.1 검색 이전의 선택을 돕는 탐색 출발점

일반적인 여행 검색은 지역명·장소명·테마처럼 사용자가 이미 알고 있는 조건을 입력하는 데서 시작합니다. CodeTrip은 지역·테마·키워드 탐색을 제공하는 동시에, 현재 위치와 날씨를 반영한 홈 추천과 관심 지역 기반 탐색 진입점을 제공합니다. 사용자는 정확한 목적지를 결정하지 못한 상태에서도 후보를 발견할 수 있습니다.

### 3.2 공공 관광 데이터와 실용 정보를 한 흐름으로 연결

한국관광공사 TourAPI의 여행지·축제·행사 정보를 바탕으로 소개, 운영 정보, 지도, 이미지, 댓글을 한 화면에 연결합니다. 단순 카드 추천에서 끝나지 않고 사용자가 실제 방문 결정을 내릴 때 필요한 장소 정보와 길찾기 맥락까지 이어지는 것이 목표입니다.

### 3.3 발견한 후보를 개인 계획으로 전환

사용자는 후보 장소를 위시리스트와 여행 폴더에 저장하고, 폴더별 메모·체크리스트를 작성할 수 있습니다. AI 플래너는 새 조건 또는 저장한 폴더를 기반으로 일정 초안을 생성합니다. 즉, 탐색 결과가 휘발되지 않고 비교·정리·일정화 단계로 이어집니다.

### 3.4 관심 지역의 변화를 다시 알려주는 순환 구조

TourAPI 신규 정보는 공용 피드로 수집하고, 사용자의 관심 지역과 일치하는 여행지·축제/행사만 Header 알림에서 확인하도록 설계했습니다. 사용자별 알림을 대량 복제하지 않아도 탐색 이후의 관심을 다시 서비스로 연결합니다.

### 3.5 설명 가능한 AI 여행 계획으로의 확장

현재 AI 플래너는 여행 조건과 저장한 여행 후보를 바탕으로 일정 초안을 생성합니다. 다음 고도화 단계에서는 인원, 동행 관계, 예산, 여행 기간, 이동수단, 여행 스타일, 우선순위, 피하고 싶은 조건을 구조화하고 다음 정보를 결과에 명시합니다.

- 추천에 반영한 조건 요약
- 장소별 추천 이유
- 날씨·계절·행사 연계 이유
- 예상 이동 부담과 대안
- 예산 적합도와 일정 조정 근거

이 단계의 목표는 “AI가 코스를 만들어줬다”가 아니라, 사용자가 **왜 이 코스가 자신의 상황에 맞는지 이해하고 조정할 수 있게 하는 것**입니다.

## 4. 현재 제공 범위와 로드맵 구분

| 영역 | 현재 제공 또는 반영 중인 범위 | 다음 고도화 목표 |
|---|---|---|
| 탐색 시작 | 지역·테마·키워드 탐색, 위치·날씨 기반 홈 추천 | 선택이 어려운 사용자를 위한 상황형 탐색 질문 강화 |
| 여행 후보 관리 | 위시리스트, 폴더, 메모, 체크리스트 | 후보 비교와 우선순위 정리 지원 |
| AI 일정 | 조건·폴더 기반 일정 초안, 관광공사 검증 장소 구분 | 동행·예산·이동 부담·여행 스타일 판단 규칙과 추천 근거 표시 |
| 신규 정보 | TourAPI 신규 정보, 관심 지역 기반 알림 구조 | 축제 전용 수집, 수신 설정, 일정·위시리스트 연계 알림 |
| 신뢰성 | 공공 관광 데이터, 지도·운영 정보, Firebase 인증·개인 데이터 관리 | 추천 데이터 출처와 판단 근거의 가시성 강화 |

미구현 목표는 서비스가 이미 제공하는 기능처럼 표현하지 않습니다. 발표·README·서비스 화면에서는 `고도화 예정`, `진행 중`, `목표`처럼 현재 상태를 함께 표시합니다.

## 5. 비교 관점

| 비교 관점 | 일반적인 여행 정보·추천 서비스 | CodeTrip의 지향점 |
|---|---|---|
| 시작 조건 | 사용자가 지역·장소·검색어를 먼저 결정 | 목적지가 막연해도 날씨·위치·관심 지역을 단서로 탐색 시작 |
| 추천 결과 | 장소 또는 코스 제시 중심 | 후보 발견 → 저장·비교 → 일정 초안 → 신규 정보 확인의 연속 흐름 |
| 개인화 기준 | 선호 또는 인기 중심 | 관심 지역에 더해 동행·예산·이동 부담·상황을 설명 가능한 기준으로 확장 |
| 신뢰와 조정 | 결과 수용 여부는 사용자 판단 | 공공 데이터·장소 출처·추천 이유를 함께 보여 사용자가 조정 가능 |
| 재방문 계기 | 새 검색 필요 | 관심 지역의 신규 장소·축제/행사 알림으로 탐색 맥락 회복 |

이 표는 특정 경쟁 서비스를 단정적으로 평가하기 위한 자료가 아니라, CodeTrip의 제품 설계 기준을 명확히 하기 위한 비교 프레임입니다.

## 6. 발표·소개용 메시지

### 30초 소개

“CodeTrip은 어디로 갈지부터 막막한 사람을 위한 여행 의사결정 지원 서비스입니다. 날씨와 위치, 관심 지역을 바탕으로 여행 후보를 발견하고, 마음에 드는 곳은 폴더에 저장해 비교한 뒤 AI 일정 초안으로 발전시킬 수 있습니다. 앞으로는 동행 관계, 예산, 이동 부담까지 반영하고 추천 이유를 보여줘 사용자가 납득하고 조정할 수 있는 여행 계획을 만들고자 합니다.”

### 짧은 슬로건 후보

- 어디로 갈지 막막한 순간부터 시작하는 여행 계획
- 여행지를 찾는 것을 넘어, 나에게 맞는 선택을 돕는 CodeTrip
- 조건을 이해하고 이유를 설명하는 여행 일정 초안

## 7. AI 플래너 고도화의 시작 기준

AI 플래너 작업은 프롬프트 문장부터 늘리기보다 아래 순서로 진행합니다.

1. 입력 구조 정의: 인원, 동행 관계, 예산, 기간, 이동수단, 여행 스타일, 우선순위, 회피 조건
2. 판단 규칙 정의: 날씨, 이동 부담, 예산, 동행 특성, 행사·계절을 어떤 우선순위로 반영할지 명시
3. 데이터 연결: 현재 날씨·장소 정보·축제 정보를 각 규칙에 필요한 범위로 연결
4. 프롬프트·응답 계약 정의: 일정뿐 아니라 조건 요약, 추천 근거, 대안, 비용·이동 정보를 구조화
5. 결과 UI 구현: 사용자가 이유를 확인하고 수정·재생성할 수 있게 표시
6. 시나리오 검증: 커플·가족·친구·혼행, 저예산·우천·짧은 일정 등 대표 조건으로 결과 품질 확인

상세 작업 우선순위는 [백로그](14-backlog.md)의 `STK-04`에서 관리합니다.
