# 기능설명서 PPTX 최종 반영 작업 지시서

이 문서는 CodeTrip 공모전 기능설명서 최종본을 만들 때, 현재 초안 PPTX에서 어떤 항목을 어떤 순서로 수정해야 하는지 정리한다. 실제 PPTX/PDF 바이너리는 `output/` 또는 외부 저장 위치에서 관리하고, Git에는 최종 산출물 manifest와 검증 기록만 남긴다. 최종본을 열람하며 슬라이드별로 확인할 항목은 `docs/35-pptx-slide-final-review-checklist.md`를 따른다.

## 기준 산출물

현재 최종본의 기준 초안은 아래 파일이다.

| 항목 | 파일 |
|---|---|
| 기준 PPTX | `output/contest/CodeTrip_2026_관광데이터_공모전_기능설명서_5페이지_제출항목정리_초안.pptx` |
| 기준 PDF | `output/contest/CodeTrip_2026_관광데이터_공모전_기능설명서_5페이지_제출항목정리_초안.pdf` |
| 현재 검증 상태 | PDF 5페이지, 394311 bytes, 텍스트 최소 12pt 이상 확인 |
| 현재 남은 이슈 | 접수 팀명 placeholder, 로그인 후 내부 화면 캡처, 최종 입력값, 양식 수정 없음 육안 검증 |

## 최종 편집 원칙

- 제공 PPTX 양식의 필수 항목을 삭제하거나 임의로 바꾸지 않는다.
- PDF 변환 후 5페이지 이하, 12포인트 이상, 10MB 미만, 정상 열람을 다시 확인한다.
- 서비스 소개 문구는 `docs/24-submission-copywriting.md`의 축약 문구를 우선 사용한다.
- 제출 페이지 입력값은 `docs/25-final-input-checklist.md`의 FI-01~FI-16과 일치시킨다.
- 비밀번호, OpenAPI 인증키, 개인 이메일, 팀원 개인정보는 PPTX와 저장소에 노출하지 않는다.
- 실제 화면 캡처에는 API 키, 개인 계정, 개인정보, 관리자 콘솔 정보가 보이지 않아야 한다.

| 2 | 서비스 소개 | 서비스 개요, 주제 선정 이유, 핵심 기능 문구를 제출용 축약 문구로 정리한다. 지역 특화 여부가 바뀌면 해당 문구도 함께 조정한다. | `docs/24-submission-copywriting.md`, `docs/23-regional-specialization-strategy.md` | 심사자가 서비스 목적과 사용자 문제를 30초 안에 이해할 수 있다. |

| 4 | 핵심 기능 흐름 | 5개 핵심 기능 흐름을 유지하되, 캡처 교체 또는 문구 수정으로 흐름이 달라졌다면 단계명을 맞춘다. | `docs/03-user-flows.md`, `docs/15-demo-scenario.md` | 탐색 → 상세 → 찜·폴더 → AI 일정 → 커뮤니티 흐름이 끊기지 않는다. |

## 슬라이드 2 권장 문구

공간이 부족하면 아래 축약 문구를 사용한다.

### 서비스 개요

CodeTrip은 한국관광공사 OpenAPI 기반 여행지 탐색 결과를 찜·폴더로 저장하고, Gemini AI로 여행 일정 초안을 생성해 커뮤니티 공유까지 연결하는 여행 계획 웹 서비스 MVP다.

### 주제 선정 이유

여행자는 여행지를 찾은 뒤 후보 저장, 일정 구성, 정보 공유를 다시 따로 진행해야 한다. CodeTrip은 이 흐름을 하나로 연결해 탐색 결과가 실제 여행 계획으로 이어지도록 돕는다.

### 핵심 기능

- 여행지 탐색
- 상세 정보·지도·날씨 확인
- 찜·폴더 기반 여행 계획 관리
- Gemini AI 여행 일정 생성
- 여행 커뮤니티와 활동 기록

## 슬라이드 3 화면 캡처 교체 우선순위

현재 초안은 비로그인 공개 화면 중심으로 구성되어 있다. 최종 제출 전 테스트 계정이 준비되면 아래 순서로 교체한다.

세부 캡처 파일명, 화면별 완료 기준, 개인정보·보안 점검 기준은 `docs/31-submission-screenshot-plan.md`를 따른다.

| 우선순위 | 교체할 화면 | 이유 | 검증 조건 |
|---:|---|---|---|
| 1 | AI 일정 생성 결과 또는 저장 화면 | 서비스 차별성과 Gemini 활용 근거를 가장 직접적으로 보여준다. | 테스트 계정 로그인 후 일정 초안 생성 또는 저장 화면을 확인한다. |
| 2 | 마이페이지 또는 찜·폴더 화면 | 탐색 결과가 개인 여행 계획으로 이어지는 흐름을 증명한다. | 찜·폴더·메모·AI 일정 중 하나 이상이 보이는 화면을 캡처한다. |
| 3 | 커뮤니티 게시글 또는 활동 화면 | 사용자 참여와 서비스 완성도를 보강한다. | 게시글 목록·상세·댓글·좋아요 중 하나 이상이 보이는 화면을 캡처한다. |
| 4 | 여행지 상세 화면 | TourAPI 상세·이미지·지도·날씨 연계 근거를 보강한다. | 로딩이 완료되고 오류 상태가 아닌 화면을 캡처한다. |

## 슬라이드 5 권장 문구

### 차별성

공공 관광 데이터 기반 탐색과 Gemini AI 일정 생성을 결합하고, 저장·커뮤니티 기능을 통해 개인 여행 준비와 사용자 참여를 한 흐름으로 연결한다.

### 발전계획

Functions 프록시, 권한 검증, 성능 측정, 코드 스플리팅, E2E 테스트를 보강하고, 향후 지역별 큐레이션과 지역 축제 특화 일정으로 확장한다.

## 최종 PDF 변환 후 검증

PPTX를 수정한 뒤에는 반드시 PDF로 변환하고 아래 항목을 다시 확인한다.

슬라이드별 세부 검수는 `docs/35-pptx-slide-final-review-checklist.md`에 기록한다.

| 검증 항목 | 기준 | 증빙 위치 |
|---|---|---|
| 페이지 수 | 5페이지 이하 | `docs/13-validation-report.md` |
| 글자 크기 | 12포인트 이상 | `docs/13-validation-report.md` |
| 파일 용량 | 10MB 미만 | `docs/17-submission-artifact-manifest.md` |
| 정상 열람 | PDF 열림, 슬라이드 잘림 없음, 원본 가이드 문구 잔존 없음 | `docs/13-validation-report.md` |
| checksum | 최종 PPTX/PDF SHA-256 기록 | `docs/17-submission-artifact-manifest.md` |
| 외부 전달 위치 | 실제 제출 위치 또는 공유 위치 기록 | `docs/17-submission-artifact-manifest.md` |

## 완료 조건

- 슬라이드 1의 팀명 placeholder가 제거되어 있다.
- 슬라이드 2의 서비스 개요와 주제 선정 이유가 제출용 축약 문구로 정리되어 있다.
- 슬라이드 3의 상세 이미지가 로그인 후 핵심 기능 화면을 포함한다.
- 슬라이드 5의 OpenAPI 활용 목록이 실제 코드와 제출 계정 기준 활용 API와 일치한다.
- 최종 PDF가 5페이지 이하, 12포인트 이상, 10MB 미만이며 정상 열람된다.
- 최종 산출물의 파일명, 생성일, checksum, 전달 위치가 `docs/17-submission-artifact-manifest.md`에 기록되어 있다.
