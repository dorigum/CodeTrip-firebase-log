# 공모전 기능설명서 화면 캡처 계획

이 문서는 CodeTrip 공모전 기능설명서 최종본에 넣을 대표 이미지와 상세 이미지 후보를 어떤 기준으로 캡처할지 정의한다. 목적은 단순히 예쁜 화면을 모으는 것이 아니라, 심사자가 서비스 완성도와 핵심 흐름을 빠르게 이해할 수 있도록 증빙력이 있는 화면을 확보하는 것이다.

## 기본 원칙

- 기능설명서에는 대표 이미지 1장과 상세 이미지 3~5장을 넣는다.
- 공개 화면만으로는 서비스 완성도를 충분히 설명하기 어렵기 때문에, 최종본에는 로그인 후 내부 기능 화면을 최소 2장 이상 포함한다.
- 모든 캡처는 실제 배포 URL 기준으로 진행한다.
- 캡처 화면에 비밀번호, OpenAPI 인증키, Firebase Console, 개인 이메일, 팀원 개인정보가 노출되면 사용하지 않는다.
- 캡처 파일은 `output/contest/screenshots/`에서 관리하고, 별도 지시 전까지 Git에 커밋하지 않는다.
- 최종 PPTX/PDF에 반영한 캡처 목록과 파일명은 `docs/17-submission-artifact-manifest.md`에 기록한다.

## 캡처 세트 구성

| 구분 | 권장 수량 | 역할 | 필수 여부 |
|---|---:|---|---|
| 대표 이미지 | 1장 | 서비스 첫인상과 핵심 콘셉트 전달 | 필수 |
| 상세 이미지 | 3~5장 | 기능 흐름과 구현 완성도 증빙 | 필수 |
| 예비 이미지 | 2~3장 | PPTX 공간 부족 또는 품질 문제 발생 시 교체 후보 | 권장 |

## 우선순위

최종 PPTX 공간이 부족하면 아래 순서로 우선 반영한다.

1. `SC-05` AI 일정 생성 결과 화면
2. `SC-04` 찜·폴더 또는 마이페이지 화면
3. `SC-02` 여행지 탐색·필터 결과 화면
4. `SC-03` 여행지 상세 화면
5. `SC-06` 커뮤니티 화면
6. `SC-01` 홈 또는 탐색 진입 화면
7. `SC-07` 축제·행사 화면

이 순서는 심사 기준 중 서비스 완성도, 데이터 활용 적절성, 서비스 차별성을 함께 보여주는 화면을 우선하기 위해 설정한다.

## 캡처 전 준비 데이터

로그인 후 화면을 캡처하기 전에 테스트 계정에 아래 데이터가 있으면 좋다.

| 데이터 | 권장 상태 | 이유 |
|---|---|---|
| 찜한 여행지 | 2~3개 이상 | 탐색 결과가 개인 계획으로 저장되는 흐름을 보여준다. |
| 폴더 | 1개 이상 | 단순 찜보다 여행 준비 관리 기능이 보인다. |
| AI 일정 | 1개 이상 | Gemini AI 기능과 저장 흐름을 증명한다. |
| 커뮤니티 게시글 | 1개 이상 | 사용자 참여 기능이 빈 화면으로 보이는 일을 막는다. |
| 댓글 또는 좋아요 | 가능하면 1개 이상 | 커뮤니티 상호작용이 구현되어 있음을 보여준다. |

데이터가 부족하면 기능이 비어 보이므로, 캡처 전에 테스트 계정으로 최소한의 시연 데이터를 만든다.

## 화면별 캡처 체크리스트

### SC-01 홈 또는 탐색 진입 화면

- 서비스명이 보인다.
- 주요 CTA 또는 여행지 탐색 진입 흐름이 보인다.
- 화면이 로딩 중이거나 오류 상태가 아니다.

### SC-02 여행지 탐색·필터 결과 화면

- 여행지 카드가 3개 이상 보이면 가장 좋다.
- 검색어 또는 필터 상태가 화면에서 이해된다.
- 빈 결과 화면은 최종 기능설명서 대표 캡처로 사용하지 않는다.

### SC-03 여행지 상세 화면

- 상세 이미지 또는 대표 이미지가 정상 표시된다.
- 지도 또는 날씨 정보가 함께 보이면 우선 사용한다.
- 외부 API 지연으로 일부 정보가 비어 있으면 재시도한다.

### SC-04 찜·폴더 또는 마이페이지 화면

- 테스트 계정 개인 데이터만 보인다.
- 저장된 여행지, 폴더, 메모, AI 일정 중 하나 이상이 보인다.
- 개인 이메일 또는 UID가 노출되면 화면을 자르거나 사용하지 않는다.

### SC-05 AI 일정 생성 결과 화면

- 생성 프롬프트 입력 화면보다 생성 결과 화면을 우선한다.
- 날짜별 일정, 장소 목록, 저장 버튼 또는 결과 카드가 보이면 좋다.
- Gemini API 오류, quota 오류, JSON 실패 화면은 제출용 대표 캡처로 사용하지 않는다.
- API 키나 원문 디버그 로그가 보이면 사용하지 않는다.

### SC-06 커뮤니티 화면

- 게시글 목록 또는 상세 화면이 비어 있지 않아야 한다.
- 댓글·좋아요·작성 버튼 중 하나 이상이 보이면 좋다.
- 작성자 개인 이메일이 보이면 사용하지 않는다.

### SC-07 축제·행사 화면

- 지역 또는 정렬 필터가 보이면 좋다.
- 축제 카드가 여러 개 보이는 상태를 우선한다.
- 네트워크 오류 화면이나 빈 결과 화면은 사용하지 않는다.

## 개인정보·보안 점검

캡처 직후 아래 항목을 반드시 확인한다.

| 점검 항목 | 기준 |
|---|---|
| 비밀번호 노출 | 없어야 한다. |
| OpenAPI 인증키 노출 | 없어야 한다. |
| Firebase Console 또는 관리자 화면 노출 | 없어야 한다. |
| 개인 이메일 노출 | 가능하면 없어야 하며, 불가피하면 캡처 후보에서 제외한다. |
| 브라우저 주소창 | URL에 토큰이나 민감한 query string이 없어야 한다. |
| 개발자 도구 | 열려 있지 않아야 한다. |
| 오류 토스트 | 제출용 핵심 캡처에는 보이지 않아야 한다. |

## PPTX 반영 기준

최종 5페이지 제한 때문에 모든 캡처를 넣을 수 없다. 슬라이드 3에는 아래 조합을 우선한다.

| 위치 | 권장 캡처 | 이유 |
|---|---|---|
| 대표 이미지 | `SC-05` 또는 `SC-02` | AI 차별성 또는 관광 데이터 탐색 콘셉트를 즉시 보여준다. |
| 상세 이미지 1 | `SC-02` | 한국관광공사 OpenAPI 기반 탐색 기능을 증명한다. |
| 상세 이미지 2 | `SC-04` | 찜·폴더·마이페이지로 개인화 흐름을 보여준다. |
| 상세 이미지 3 | `SC-05` | AI 일정 생성 기능을 직접 보여준다. |
| 상세 이미지 4 | `SC-06` | 커뮤니티와 사용자 참여 흐름을 보강한다. |
| 상세 이미지 5 | `SC-03` 또는 `SC-07` | 상세 정보·축제 데이터 활용을 보완한다. |

대표 이미지와 상세 이미지가 중복되면, 대표 이미지는 홈·탐색 또는 AI 결과 중 시각적으로 가장 이해하기 쉬운 화면으로 선택한다.

## 현재 상태

현재 초안에는 공개 화면 중심 캡처가 들어가 있으며, 로그인 후 AI·마이페이지·커뮤니티 내부 화면은 테스트 전용 계정 준비 후 교체해야 한다. 따라서 이 문서의 `SC-04`, `SC-05`, `SC-06`이 다음 캡처 작업의 핵심 차단 항목이다.
