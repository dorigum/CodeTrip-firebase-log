# 심사용 테스트 계정 검증 절차

이 문서는 공모전 1차 심사 제출 전 CodeTrip 테스트 계정을 생성하고 로그인 필요 기능을 검증하기 위한 절차다. 실제 이메일, 비밀번호, 인증키, 개인 식별 정보는 저장소에 기록하지 않는다. 테스트 계정 내부에 넣을 시연 데이터 기준은 `docs/33-test-account-demo-data-runbook.md`를 따른다.

## 목적

공모전 제출 항목의 “서비스 테스트 계정 정보”가 누락되거나 로그인 불가 상태가 되면 심사 제외 리스크가 발생한다. 따라서 제출 전 테스트 전용 계정을 생성하고, 로그인 이후 핵심 기능 화면이 접근 가능한지 확인한다.

## 계정 생성 기준

| 항목 | 기준 |
|---|---|
| 계정 용도 | 공모전 심사용 테스트 전용 |
| 개인 계정 사용 | 금지 |
| 권장 ID 형식 | 제출 안내의 이메일 계정 형식 사용 |
| 비밀번호 | 제출 안내 지정 비밀번호 사용. 저장소에는 기록하지 않음 |
| 표시 이름 | 심사용 계정임을 알 수 있는 일반 이름 사용 |
| 저장 위치 | 제출 페이지에만 입력 |

## 생성 전 확인

- Firebase Authentication에서 이메일/비밀번호 로그인이 활성화되어 있어야 한다.
- Firebase Realtime Database Rules가 `users/{uid}` 프로필 생성과 로그인 후 읽기를 허용해야 한다.
- 배포 URL은 제출 직전 기준으로 `https://dorigum-codetrip.web.app` 접속이 가능해야 한다.
- 브라우저 자동완성이나 개인 계정 세션이 섞이지 않도록 새 시크릿 창 또는 별도 브라우저 프로필을 사용한다.

## 계정 생성 절차

1. 배포 URL에 접속한다.
2. `Sign In` 또는 로그인 메뉴로 이동한다.
3. `Create Account`를 선택한다.
4. `Full Name`, `Email Address`, `Password`, `Confirm Password`를 입력한다.
5. `Create Account`를 실행한다.
6. 회원가입 완료 모달이 표시되는지 확인한다.
7. `로그인하기`를 선택해 로그인 화면으로 이동한다.
8. 생성한 테스트 계정으로 로그인한다.
9. 로그인 후 홈 화면으로 이동하는지 확인한다.

## 로그인 후 기능 검증

| ID | 검증 화면 | 확인 항목 | 결과 기록 위치 |
|---|---|---|---|
| TA-01 | 홈 | 로그인 상태에서 홈 화면이 정상 표시된다. | `docs/13-validation-report.md` |
| TA-02 | 여행지 탐색 | 목록과 필터가 정상 표시되고 찜 버튼 접근이 가능하다. | `docs/13-validation-report.md` |
| TA-03 | 찜/폴더 또는 마이페이지 | 사용자 소유 데이터 화면에 접근 가능하다. | `docs/13-validation-report.md` |
| TA-04 | AI Planner | 접근 제한 모달이 아니라 AI 일정 입력 또는 결과 화면에 접근 가능하다. | `docs/13-validation-report.md` |
| TA-05 | 커뮤니티 | 게시글 목록, 작성, 상세, 댓글 중 최소 1개 흐름을 확인한다. | `docs/13-validation-report.md` |
| TA-06 | 로그아웃 후 재로그인 | 제출용 계정 정보로 다시 로그인 가능하다. | `docs/13-validation-report.md` |

## 기능설명서 화면 캡처 교체 기준

테스트 계정 검증이 끝나면 현재 기능설명서 3페이지의 비로그인/접근 제한 화면 일부를 로그인 후 실제 기능 화면으로 교체한다.

| 우선순위 | 캡처 화면 | 교체 목적 |
|---|---|---|
| 1 | AI 일정 생성 결과 또는 저장 화면 | AI 기능의 실제 동작과 차별성 증명 |
| 2 | 마이페이지 또는 찜/폴더 화면 | 사용자 개인화 저장 기능 증명 |
| 3 | 커뮤니티 게시글 또는 댓글 화면 | 사용자 참여 기능 증명 |
| 4 | 상세 페이지 로딩 완료 화면 | TourAPI 상세·이미지·지도·날씨 연계 증명 |

캡처 시 개인 이메일, UID, API 키, 브라우저 저장소, Firebase 콘솔 화면은 노출하지 않는다.

## 제출 전 판정

| 판정 | 조건 |
|---|---|
| 통과 | 테스트 전용 계정으로 로그인하고 TA-01~TA-06을 모두 확인했다. |
| 부분 통과 | 로그인은 가능하지만 AI, 마이페이지, 커뮤니티 중 일부 기능 검증이 미완료다. |
| 실패 | 계정 생성 또는 로그인이 불가능하다. 제출 전 반드시 수정해야 한다. |

## 문서 갱신 규칙

- 실제 계정 ID와 비밀번호는 이 문서에 기록하지 않는다.
- 검증 결과는 `docs/13-validation-report.md`에 날짜, 환경, 확인 흐름, 실패 지점으로 기록한다.
- 최종 화면 캡처를 반영한 기능설명서 파일은 `docs/17-submission-artifact-manifest.md`에 파일명, 생성일, checksum, 외부 전달 위치를 기록한다.
- 테스트 계정 검증이 완료되면 `docs/16-contest-submission-checklist.md`의 CS-04 상태를 갱신한다.
- 테스트 계정에 찜·폴더·AI 일정·커뮤니티 시연 데이터를 준비할 때는 `docs/33-test-account-demo-data-runbook.md`를 참조한다.
