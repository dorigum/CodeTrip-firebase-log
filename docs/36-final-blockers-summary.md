# 공모전 최종 제출 차단 항목 요약

이 문서는 CodeTrip 공모전 기능설명서 최종 제출 전 남아 있는 차단 항목을 우선순위와 책임 범위별로 정리한 요약 문서다. `docs/28-submission-readiness-dashboard.md`가 전체 현황판이라면, 이 문서는 실제로 다음에 무엇을 해결해야 하는지 빠르게 판단하기 위한 실행 요약이다.

## 현재 판정

현재 상태는 `제출 초안 준비 완료, 최종 제출 보류`다.

문서 체계와 제출용 초안은 준비되어 있지만, 제출 가능 판정을 내리려면 외부 제출 페이지와 실제 서비스 상태에서 확인해야 하는 값이 남아 있다. 특히 접수 팀명, 테스트 계정, OpenAPI 인증키, 로그인 후 화면 캡처, 최종 PDF 검증은 문서만으로 완료 처리할 수 없다. Gemini 호출부는 Firebase Callable Function 프록시로 전환되어 배포되었고, Secret 등록과 미인증 차단도 확인했다. 남은 AI 보안 차단 항목은 로그인 상태 실제 AI 생성 smoke test와 기존 노출 가능 키 폐기·거부 확인이다.

## 차단 항목 그룹

| 그룹 | 성격 | 대표 항목 | 현재 판정 |
|---|---|---|---|
| G1 사용자·팀 확인값 | 접수 페이지와 팀 내부에서만 확인 가능 | 팀명, 팀원 정보, 중복 출품 여부, 마감 전 제출 시간 | 부분 확인 |
| G2 계정·서비스 검증 | 실제 배포 URL과 테스트 계정으로 확인 필요 | 테스트 계정, 시연 데이터, URL smoke test | 미완료 |
| G3 OpenAPI 제출 정보 | 공공데이터포털과 배포 환경 대조 필요 | 인코딩키·디코딩키, 활용 API 목록, 최종 PDF API 문구 | 부분 준비 |
| G4 기능설명서 최종 산출물 | PPTX/PDF 최종본 생성 후 확인 가능 | 팀명 반영, 캡처 교체, 5페이지, 12pt, 10MB, checksum | 미완료 |
| G5 제출 리스크 | 제출 페이지에서 최종 확인 필요 | 부문 오첨부, 양식 일치, 제출 후 수정 제한 | 미확인 |
| G6 AI 공개 시연 보안 | 공개 배포 환경에서 클라이언트 키 노출 차단 필요 | Callable Function·Secret·Hosting 배포 완료, 배포 산출물 키 미포함과 미인증 401 차단 확인, 기존 키 폐기와 로그인 성공 케이스 검증 필요 | 부분 완료 |

## 제출 가능 판정 기준

최종 제출 가능으로 전환하려면 아래 조건이 모두 충족되어야 한다.

1. 접수 팀명과 최종 팀원 정보가 제출 페이지 기준으로 확인되어 있다.
2. 테스트 전용 계정으로 로그인·로그아웃·재로그인이 가능하다.
3. 테스트 계정에 찜·폴더·AI 일정·커뮤니티 시연 데이터가 준비되어 있다.
4. OpenAPI 인증키는 제출 페이지에만 입력되고, 기능설명서에는 활용 API 목록만 기록되어 있다.
5. 제출 후보 URL에서 공개 화면, 직접 경로 새로고침, 로그인 후 핵심 기능이 확인되어 있다.
6. 공개 URL에서 Gemini 생성 기능을 제공할 경우 Functions 프록시 배포, 서버 측 Secret 저장, 기존 노출 가능 키 폐기·거부 확인이 완료되어 있다.
7. 최종 PPTX/PDF에 팀명, 로그인 후 캡처, OpenAPI 목록, 발전계획이 반영되어 있다.
8. PDF가 5페이지 이하, 12포인트 이상, 10MB 미만이며 정상 열람된다.
9. 최종 산출물의 파일명, 크기, SHA-256, 외부 전달 위치가 manifest에 기록되어 있다.
10. 동일 서비스 중복 출품 없음, 웹·앱 개발 부문 양식 일치, 마감 전 수정 가능 시간이 확인되어 있다.
11. `docs/27-final-validation-execution-sheet.md`의 제출 직전 차단 조건이 모두 `통과` 또는 `완료` 상태다.

## 현재 다음 작업 제안

문서 작업 기준으로는 차단 항목을 추적할 구조가 충분히 갖춰졌다. 다음 실제 실행 단계는 아래 순서가 적합하다.

1. 사용자 제공 입력값 확인
2. 테스트 전용 계정 생성
3. 테스트 계정 시연 데이터 세팅
4. 최신 배포 URL smoke test
5. 로그인 후 화면 캡처 확보
6. 최종 PPTX/PDF 생성과 검수

이 단계부터는 실제 계정, 제출 페이지, 배포 URL, 산출물 파일을 다루므로 실행 결과를 문서에 반영할 때 민감정보 원문을 남기지 않는다.

## 민감정보 전달·보관 기준

테스트 계정 비밀번호, OpenAPI 인증키, Gemini API 키 같은 민감정보는 저장소, 검증 보고서, 화면 캡처, PR 댓글에 원문으로 기록하지 않는다.

| 항목 | 보관·전달 기준 | 담당 | 만료·교체 기준 | 문서 기록 방식 |
|---|---|---|---|---|
| 테스트 계정 비밀번호 | 승인된 비밀번호 관리자에 보관하고 제출 담당자에게만 공유한다. 임시 채팅, GitHub, 문서 파일에는 기록하지 않는다. | 제출 담당자 | 제출 완료 후 비밀번호 교체 또는 계정 비활성화 여부 결정 | 로그인 성공 여부와 마스킹된 계정 식별자만 기록 |
| 한국관광공사 OpenAPI 인증키 | 공공데이터포털과 제출 페이지에서만 확인·입력한다. 별도 보관이 필요하면 승인된 비밀번호 관리자 또는 Secret Manager에 저장한다. | API 담당자 | 키 유출 의심, 담당자 변경, 제출 완료 후 필요 시 재발급 | 키 원문 없이 확인 일자, API명, 마스킹된 끝자리만 기록 |
| Gemini API 키 | 공개 클라이언트 번들에 포함하지 않는다. Functions 프록시를 사용할 경우 서버 측 Secret에 저장한다. | 개발 담당자 | 공개 노출 의심, 프록시 전환, 제출 완료 후 운영 정책에 따라 교체 | Secret 등록 여부, 프록시 배포 여부, 생성 기능 활성/비활성 상태만 기록 |

검증 보고서와 캡처에는 성공·실패 결과, 검증 일자, 담당자, 마스킹된 식별자만 기록한다. 민감정보가 화면에 노출된 캡처는 제출 산출물과 manifest 후보에서 제외한다.
