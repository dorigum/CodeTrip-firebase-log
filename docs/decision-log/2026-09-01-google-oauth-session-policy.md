# Google OAuth 세션 및 기존 계정 가입 정책

## 배경

CodeTrip은 기존 이메일·비밀번호 로그인에 더해 Google OAuth 로그인을 선택 수단으로 추가했습니다. OAuth 인증 결과를 앱 상태와 Realtime Database 프로필에 연결하는 과정에서 다음 문제가 확인됐습니다.

- 앱이 Firebase ID 토큰을 `localStorage`에 직접 저장하면 XSS 발생 시 bearer 토큰 노출 범위가 넓어집니다.
- 신규 Google 계정의 인증 직후에는 Realtime Database가 새 인증 상태를 아직 반영하지 않아 일시적인 `PERMISSION_DENIED`가 발생할 수 있습니다.
- 기존 Google 계정으로 회원가입을 재시도하면 계정 선택, 세션 정리, 인증 리스너의 비동기 결과가 경합해 홈으로 이동하거나 일반 오류가 표시될 수 있습니다.

## 선택지

1. 앱이 ID 토큰을 직접 보관하고 API 호출마다 전달합니다.
2. Firebase SDK의 기본 영구 저장소를 사용해 브라우저를 닫은 뒤에도 인증 상태를 유지합니다.
3. Firebase SDK의 세션 저장소를 사용하고, 앱은 사용자 UI 상태와 2시간 세션 만료만 관리합니다.

기존 계정의 Google 회원가입 시도에 대해서도 자동 로그인·홈 이동, 일반 인증 오류 표시, 기존 계정 안내 후 세션 정리 중 하나를 선택해야 했습니다.

## 결정

- Firebase Authentication의 `browserSessionPersistence`를 사용합니다.
- 앱은 Firebase ID 토큰을 반환값이나 Web Storage에 직접 저장하지 않습니다. 토큰 수명과 갱신은 Firebase SDK에 맡기고, 앱은 `trip_user`와 세션 만료 상태만 관리합니다.
- Google OAuth 제공업체에 `prompt=select_account`를 지정해 로그인·회원가입 시 사용자가 계정을 선택하게 합니다.
- 회원가입 흐름에서 `isNewUser`가 `false`이면 Realtime Database 프로필 조회를 생략하고, 인증 상태를 정리한 뒤 기존 Google 계정 로그인 안내를 표시합니다.
- 신규 계정의 프로필 조회·생성 중 일시적 권한 오류는 토큰 갱신 후 제한적으로 재시도합니다. 재시도 후에도 실패하면 세션을 정리하고 오류를 표시합니다.

## 영향

- 인증 정보는 현재 브라우저 세션 안에서만 유지되므로, 브라우저를 닫은 뒤에는 다시 로그인해야 합니다.
- Google-only 계정의 비밀번호 변경은 지원하지 않고 Google 계정에서 관리한다는 안내를 표시해야 합니다.
- 기존 Google 계정의 재가입 시도는 홈으로 이동하지 않고 `이미 Google 계정으로 가입되어 있습니다.` 안내를 표시합니다.
- Firebase SDK가 관리하는 세션 저장소는 존재할 수 있지만, 앱 코드가 bearer 토큰을 직접 보관하지 않는다는 보안 기준을 유지합니다.

## 재검토 조건

- 여러 탭 또는 브라우저 재시작 후에도 인증을 공유해야 하는 제품 요구사항이 생기는 경우
- 서버 세션 쿠키 또는 별도 백엔드 API가 도입되어 토큰 전달·세션 만료 정책을 다시 설계해야 하는 경우
- 이메일·비밀번호 계정과 Google 계정의 동일 이메일을 명시적으로 연결하는 기능을 지원하기로 결정하는 경우
