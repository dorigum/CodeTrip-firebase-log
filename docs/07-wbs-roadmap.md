# WBS·로드맵

| 기간 | 목표 | 산출물 |
|---|---|---|
| 1주차 | 현황·범위·기준선 확정 | 헌장, 기능 목록, 기술부채 목록 |
| 2주차 | 요구사항·아키텍처 정리 | 요구사항, 사용자 흐름, 구조도 |
| 3~4주차 | 핵심 여정 안정화 | 탐색·인증·저장·AI·커뮤니티 검증 |
| 5주차 | 품질·보안 검증 | 테스트 결과, Rules 점검, 성능 기준선, 번들 크기 측정 |
| 6주차 | 배포·운영 정비 | 릴리스 체크리스트, 장애 대응, 시연 시나리오 |
| 7~8주차 | 심사 패키지·회고 | KPI 보고서, 발표 자료, 다음 백로그 |

각 스프린트는 계획, 구현, 검증, 문서 갱신, 회고를 완료 조건으로 한다. Must 항목이 먼저이며 Should 항목은 품질 리스크가 낮을 때만 진행한다.
