# 공모전 지역 특화 제출 전략

이 문서는 2026 관광데이터 활용 공모전 제출 시 CodeTrip을 전국 단위 서비스로 제출할지, 특정 지역 특화 서비스로 조정할지 판단하기 위한 기준을 정리합니다.

## 현재 결론

현재 CodeTrip MVP의 기본 제출 방향은 전국 단위 여행 서비스입니다.

지역 특화 가점은 매력적이지만, 현재 구현과 기능설명서 초안은 전국 단위 탐색, 축제 조회, 찜·폴더 저장, AI 일정 생성, 커뮤니티 흐름을 중심으로 구성되어 있습니다. 따라서 특정 지역 특화로 제출하려면 단순히 문구만 바꾸는 것이 아니라 서비스 정보, 핵심 화면, 사용자 문제 정의, 기능설명서 이미지, 시연 시나리오까지 함께 정렬해야 합니다.

현 시점의 권장 전략은 다음과 같습니다.

1. 1차 제출은 전국 단위 서비스로 유지합니다.
2. 지역 특화는 발전계획 또는 후속 버전 백로그로 제시합니다.
3. 사용자가 특정 비서울 지역을 명확히 선택하고, 해당 지역 중심 화면 증빙을 준비할 수 있을 때만 지역 특화 제출로 전환합니다.

## 선택지 비교

| 선택지 | 설명 | 장점 | 리스크 | 현재 적합도 |
|---|---|---|---|---|
| 전국 단위 제출 | 현재 구현과 초안 그대로 전국 여행지 탐색 서비스로 제출 | 구현·문서·스크린샷 정합성이 높고 추가 수정 부담이 작습니다. | 지역 특화 가점은 받을 수 없습니다. | 높음 |
| 특정 지역 특화 제출 | 서울을 제외한 특정 지역을 서비스 정보와 기능설명서에 명시 | 지역 특화 가점 가능성이 있습니다. | 화면, 문구, 데이터 활용 근거, 시연 흐름을 다시 맞춰야 합니다. | 조건부 |
| 전국 단위 제출 + 지역 특화 발전계획 | 현재 서비스는 전국 단위로 제출하고, 향후 특정 지역 큐레이션으로 확장한다고 설명 | 현재 완성도를 유지하면서 발전성을 설명할 수 있습니다. | 가점 항목 자체는 선택하지 않을 가능성이 높습니다. | 높음 |

## 지역 특화 제출로 전환할 수 있는 조건

아래 조건이 모두 충족될 때만 지역 특화 제출을 검토합니다.

- 서울을 제외한 특정 지역명이 확정되어 있습니다.
- 해당 지역을 선택한 이유가 사용자 문제와 연결되어 있습니다.
- 핵심 화면에서 해당 지역 중심 탐색 또는 추천 결과를 보여줄 수 있습니다.
- 기능설명서의 대표 이미지 또는 상세 이미지에 해당 지역 특화 구현 근거가 드러납니다.
- 한국관광공사 OpenAPI 활용 목록과 실제 서비스 화면이 같은 지역 전략을 뒷받침합니다.
- 제출 마감 전까지 PPTX, PDF, 제출 페이지 입력 항목, 시연 시나리오를 모두 재검증할 시간이 있습니다.

## 지역 특화 제출 시 수정 대상

지역 특화 제출을 선택하면 아래 항목을 함께 수정해야 합니다.

| 수정 대상 | 필요한 작업 |
|---|---|
| 제출 페이지 서비스 정보 | 지역 특화 서비스 유무를 `예`로 선택하고, 서울 제외 특정 지역명을 입력합니다. |
| 기능설명서 서비스 소개 | 주제 선정 이유와 서비스 개요에 해당 지역 문제를 반영합니다. |
| 기능설명서 지역 특화 항목 | 특화 지역명과 구현 내용을 작성합니다. |
| 기능설명서 이미지 | 해당 지역 중심 탐색 결과, 축제, 상세 화면, AI 일정 예시를 캡처합니다. |
| 시연 시나리오 | 첫 탐색 조건을 해당 지역으로 고정하고, AI 일정 생성 예시도 해당 지역 중심으로 구성합니다. |
| 체크리스트·갭 분석 | 지역 특화 결정 상태와 증빙 위치를 갱신합니다. |

## 현재 제출 문구 방향

전국 단위 제출을 유지할 경우 다음 방향으로 작성합니다.

- 지역 특화 서비스 유무: 아니오
- 서비스 개요: 전국 관광 데이터를 기반으로 여행지 탐색, 저장, AI 일정 생성, 커뮤니티 공유를 연결하는 웹 서비스
- 차별성: 한국관광공사 OpenAPI 기반 데이터 탐색과 Gemini AI 일정 생성, Firebase 기반 개인화 저장·커뮤니티 흐름의 결합
- 발전계획: 향후 지역별 큐레이션, 지역 축제 특화 일정, 로컬 관광 사업자 연계 기능으로 확장

지역 특화 제출로 전환할 경우 다음 항목은 반드시 실제 지역명으로 구체화합니다.

- 특화 지역명
- 지역을 선택한 이유
- 해당 지역의 관광 데이터 활용 방식
- 해당 지역 중심 사용자 흐름
- 해당 지역 중심 화면 캡처
