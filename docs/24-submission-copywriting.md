# 공모전 기능설명서 제출용 문구

이 문서는 CodeTrip 기능설명서와 한국관광 콘텐츠랩 입력 항목에 사용할 서비스 소개, 주제 선정 이유, 차별성, 발전계획 문구를 정리한다. 실제 제출 시에는 제공 PPTX 양식의 공간에 맞춰 문장을 줄이되, 측정되지 않은 정량 성과나 검증되지 않은 완료율은 추가하지 않는다.

## 작성 원칙

- 심사자가 30초 안에 서비스 목적을 이해할 수 있도록 사용자 문제를 먼저 쓴다.
- 기술명은 기능적 의미가 있을 때만 사용한다.
- “완벽하다”, “상용 수준이다”, “100% 검증”처럼 증빙 없는 표현은 사용하지 않는다.
- 현재 구현된 MVP와 향후 발전계획을 분리해서 쓴다.
- Gemini API 키 노출, Functions 프록시 이전, 성능 측정 등 남은 과제는 발전계획으로 정직하게 표현한다.
- 공개 URL에서 AI 생성 기능을 제공하기 전에는 Gemini API 키를 Firebase Functions 프록시와 Functions Secret 기반 호출로 이전한다. 이 이전이 완료되지 않으면 공개 URL의 Gemini 신규 생성 기능은 비활성화하고, 기능설명서에는 기존 저장 결과 또는 발전계획으로만 설명한다.

## 서비스 한 줄 소개

CodeTrip은 한국관광공사 OpenAPI 기반 여행지 탐색 결과를 찜·폴더로 저장하고, Gemini AI로 일정 초안을 생성해 커뮤니티 활동까지 연결하는 여행 계획 웹 서비스다.

## 서비스 개요

CodeTrip은 국내 여행지를 탐색하는 단계에서 멈추지 않고, 사용자가 관심 여행지를 저장한 뒤 AI 일정 초안으로 확장할 수 있도록 돕는 웹 서비스 MVP다. 한국관광공사 OpenAPI를 활용해 여행지, 상세 정보, 이미지, 축제 데이터를 제공하고, Firebase 기반 인증·데이터 저장 구조로 개인별 찜·폴더·AI 일정·커뮤니티 활동을 관리한다.

서비스의 핵심 흐름은 여행지 탐색, 상세 조회, 찜·폴더 저장, Gemini AI 일정 생성, 커뮤니티 공유다. 이를 통해 사용자는 흩어진 여행 정보를 직접 다시 정리하는 부담을 줄이고, 탐색 결과를 실제 여행 계획으로 이어갈 수 있다.

## 주제 선정 이유

국내 여행 정보는 공공 데이터, 지도, 날씨, 커뮤니티 등 여러 출처에 흩어져 있다. 사용자는 여행지를 찾은 뒤에도 후보지를 따로 저장하고, 이동 순서와 일정 초안을 다시 구성해야 한다. CodeTrip은 이 과정을 하나의 흐름으로 연결해 “찾는 서비스”에서 “계획으로 이어지는 서비스”로 확장하는 것을 목표로 한다.

또한 최근 여행 서비스는 단순 검색보다 개인화 추천, 생성형 AI 기반 일정화, 사용자 참여형 콘텐츠가 중요해지고 있다. CodeTrip은 공공 관광 데이터를 기반으로 신뢰 가능한 기본 정보를 제공하고, AI를 활용해 사용자의 조건에 맞는 일정 초안을 빠르게 생성하도록 설계했다.

## 핵심 기능 설명 문구

### 1. 여행지 탐색

지역, 테마, 키워드 조건을 기반으로 한국관광공사 OpenAPI의 관광 데이터를 조회한다. 사용자는 관심 있는 여행지를 빠르게 탐색하고, 빈 결과나 오류 상태도 화면에서 확인할 수 있다.

### 2. 상세 정보 확인

여행지 상세 정보, 이미지, 지도, 날씨 정보를 한 화면에서 확인한다. 외부 API 응답 지연이나 실패 가능성을 고려해 캐시와 오류 안내 기준을 함께 관리한다.

### 3. 찜·폴더 기반 계획 관리

로그인 사용자는 관심 여행지를 찜하고 폴더에 저장할 수 있다. 저장된 여행지는 메모와 체크리스트를 통해 개인 여행 준비 자료로 관리된다.

### 4. Gemini AI 여행 일정 생성

사용자 조건과 후보 여행지를 바탕으로 Gemini AI가 여행 일정 초안을 생성한다. 생성 결과는 JSON 계약과 장소 검증 기준에 따라 관리하며, 실패 시 사용자에게 안내하는 fallback 흐름을 둔다.

### 5. 여행 커뮤니티와 활동 기록

사용자는 여행 관련 게시글을 작성하고 댓글, 좋아요, 여행지 태그를 통해 다른 사용자와 정보를 공유할 수 있다. 작성자별 수정·삭제 권한과 개인 활동 기록을 분리해 관리한다.

## 서비스 차별성

CodeTrip의 차별성은 여행지 탐색, 개인 저장, AI 일정화, 커뮤니티 공유를 하나의 사용자 여정으로 연결한 점이다. 단순히 관광 정보를 보여주는 데 그치지 않고, 사용자가 관심 여행지를 직접 저장하고 이를 AI 일정 생성의 입력으로 활용할 수 있도록 구성했다.

기술적으로는 한국관광공사 OpenAPI를 중심 데이터로 사용하고, Gemini API는 일정 초안 생성에 제한적으로 활용한다. AI가 생성한 장소와 TourAPI 기반 검증 장소를 구분해 관리함으로써 생성형 AI 결과를 그대로 노출하는 위험을 줄이고자 했다.

또한 Firebase Authentication, Realtime Database, Hosting을 활용해 인증, 개인 데이터, 커뮤니티, 배포를 빠르게 통합했다. 현재 MVP에서는 기능 구현과 심사 시연 가능성을 우선했고, 향후 Functions 프록시, Rules 검증, 성능 측정, E2E 테스트를 통해 운영 안정성을 고도화할 계획이다.

## 발전계획

1. 최종 제출 전 공개 URL에서 Gemini 생성 기능을 제공하려면 Gemini API 호출을 Firebase Functions 프록시로 이전하고, Functions Secret 기반 서버 호출로 전환해 클라이언트 번들에서 키를 제거한다. 미완료 시 공개 생성 기능은 비활성화한다.
2. Firebase Rules 검증표와 핵심 사용자 여정 테스트를 보강해 인증, 개인 데이터, 커뮤니티 권한을 더 명확하게 검증한다.
3. Lighthouse, 빌드 로그, API 캐시 이벤트를 기준으로 초기 로딩 시간, 번들 크기, API 응답, 캐시 효과를 릴리스별로 측정한다.
4. 라우트 단위 코드 스플리팅과 lazy loading을 적용해 Vite 번들 크기 경고를 줄이고 초기 로딩 성능을 개선한다.
5. 전국 단위 서비스에서 출발하되, 향후 특정 지역 큐레이션, 지역 축제 특화 일정, 로컬 관광 사업자 연계 기능으로 확장한다.

기능설명서 공간이 부족할 경우 아래 문구를 우선 사용한다.

### 서비스 개요 축약

CodeTrip은 한국관광공사 OpenAPI 기반 여행지 탐색 결과를 찜·폴더로 저장하고, Gemini AI로 여행 일정 초안을 생성해 커뮤니티 공유까지 연결하는 여행 계획 웹 서비스 MVP다.

### 주제 선정 이유 축약

여행자는 여행지를 찾은 뒤 후보 저장, 일정 구성, 정보 공유를 다시 따로 진행해야 한다. CodeTrip은 이 흐름을 하나로 연결해 탐색 결과가 실제 여행 계획으로 이어지도록 돕는다.

### 차별성 축약

공공 관광 데이터 기반 탐색과 Gemini AI 일정 생성을 결합하고, 저장·커뮤니티 기능을 통해 개인 여행 준비와 사용자 참여를 한 흐름으로 연결한다.

### 발전계획 축약

Gemini Functions 프록시 이전, 권한 검증, 성능 측정, 코드 스플리팅, E2E 테스트를 보강하고, 향후 지역별 큐레이션과 지역 축제 특화 일정으로 확장한다.
