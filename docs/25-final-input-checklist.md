# 공모전 최종 입력값 체크표

이 문서는 CodeTrip 1차 심사 자료를 한국관광 콘텐츠랩에 제출하기 직전, 제출 페이지와 기능설명서에 실제로 입력해야 하는 값의 준비 상태를 점검하기 위한 체크표입니다.

비밀번호, OpenAPI 인증키, 개인 이메일, 팀원 개인정보 등 민감정보는 저장소에 기록하지 않습니다. 이 문서에는 실제 값 대신 확인 상태, 확인자, 반영 위치, 증빙 문서만 기록합니다.

최종 제출 직전 실제 검증 실행 결과는 `docs/27-final-validation-execution-sheet.md`에 기록합니다.
전체 제출 준비도와 남은 차단 항목은 `docs/28-submission-readiness-dashboard.md`에서 요약합니다.

## 사용 원칙

- 실제 값은 제출 페이지, 공공데이터포털, Firebase Console 등 원본 시스템에서 확인합니다.
- 저장소에는 민감정보 원문을 남기지 않습니다.
- 기능설명서 PDF와 제출 페이지 입력값이 서로 다르면 제출 전 반드시 맞춥니다.
- `완료`로 표시하려면 확인 일자, 확인자, 증빙 위치가 있어야 합니다.
- 최종 제출 직전에는 이 문서와 `docs/22-final-submission-runbook.md`를 함께 확인합니다.
- 제출 가능 여부를 최종 판정할 때는 `docs/27-final-validation-execution-sheet.md`의 제출 직전 차단 조건을 따릅니다.
- 남은 차단 항목의 우선순위는 `docs/28-submission-readiness-dashboard.md`의 B-01~B-10을 기준으로 봅니다.

## 최종 확인 기록 양식

최종 제출 직전 아래 형식으로 확인 결과를 남깁니다. 실제 비밀번호와 인증키는 기록하지 않습니다.

| 확인일 | 확인자 | 확인 범위 | 결과 | 후속 조치 |
|---|---|---|---|---|
| YYYY-MM-DD | 이름 | FI-01~FI-19 | 미진행 | 최종 제출 전 작성 |

## 현재 다음 조치

1. 접수 페이지에서 팀명과 최종 팀원 정보를 확인합니다.
2. 테스트 전용 계정을 생성하고 `docs/19-test-account-verification.md` 기준으로 검증합니다.
3. OpenAPI 인코딩키·디코딩키와 활용 API 목록을 제출 페이지 기준으로 확인합니다.
4. 지역 특화 여부를 전국 단위 제출로 확정할지, 특정 지역 특화로 전환할지 결정합니다.
5. 로그인 후 내부 화면 캡처를 확보해 기능설명서 3페이지 이미지를 교체합니다.
6. 최종 PPTX/PDF를 생성하고 `docs/17-submission-artifact-manifest.md`에 checksum과 전달 위치를 기록합니다.
