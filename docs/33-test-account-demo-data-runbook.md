# 공모전 테스트 계정 시연 데이터 세팅 절차

이 문서는 CodeTrip 공모전 기능설명서 최종 캡처와 심사자 테스트를 위해 제출용 테스트 계정에 어떤 데이터를 준비해야 하는지 정의한다. 테스트 계정이 로그인만 가능하고 내부 데이터가 비어 있으면 찜·폴더, AI 일정, 커뮤니티 기능의 완성도를 설명하기 어렵다.

## 목적

- 심사자가 제출용 테스트 계정으로 로그인했을 때 핵심 기능을 바로 확인할 수 있게 한다.
- 기능설명서 3페이지의 로그인 후 화면 캡처가 빈 화면이 아니라 실제 사용 흐름을 보여주도록 한다.
- 테스트 계정 데이터가 개인정보나 실제 여행 계획처럼 보이지 않도록 안전한 시연용 데이터로 구성한다.

## 기본 원칙

- 테스트 계정 비밀번호는 저장소에 기록하지 않는다.
- 시연 데이터에는 실제 개인정보, 실제 연락처, 실제 예약 정보, 결제 정보, 민감한 일정 정보를 넣지 않는다.
- 화면 캡처에 개인 이메일, UID, API 키, 관리자 화면이 보이면 해당 캡처는 사용하지 않는다.
- 테스트 데이터는 제출 전 검증 목적의 최소 데이터로 유지한다.
- 최종 제출 이후에도 계정이 유지되어야 하므로, 제출 직전에는 테스트 데이터를 삭제하지 않는다.

## 권장 시연 데이터 세트

| ID | 데이터 영역 | 권장 수량 | 목적 | 연결 캡처 |
|---|---|---:|---|---|
| DD-01 | 찜한 여행지 | 2~3개 | 탐색 결과 저장 흐름 증명 | `SC-04` |
| DD-02 | 여행 폴더 | 1개 | 찜한 장소를 계획 단위로 묶는 흐름 증명 | `SC-04` |
| DD-03 | 폴더 메모 또는 체크리스트 | 1~2개 | 개인 여행 준비 기능 증명 | `SC-04` |
| DD-04 | AI 일정 | 1개 | Gemini 기반 일정 생성과 저장 흐름 증명 | `SC-05` |
| DD-05 | 커뮤니티 게시글 | 1개 | 사용자 참여 기능 증명 | `SC-06` |
| DD-06 | 댓글 또는 좋아요 | 가능하면 1개 | 커뮤니티 상호작용 증명 | `SC-06` |

## 권장 데이터 예시

아래 예시는 제출용 화면이 자연스럽게 보이도록 하기 위한 문구다. 실제 개인정보나 민감정보를 포함하지 않는다.

| 영역 | 예시 |
|---|---|
| 폴더명 | `공모전 시연용 제주 여행 후보`, `CodeTrip 데모 여행 계획` |
| 메모 | `가족 여행 후보지 비교`, `AI 일정 생성 전 저장한 장소` |
| 체크리스트 | `동선 확인`, `날씨 확인`, `축제 일정 확인` |
| AI 일정 조건 | `2박 3일`, `자연·맛집·산책`, `이동 부담 적게` |
| 커뮤니티 게시글 제목 | `CodeTrip으로 만든 여행 일정 공유합니다` |
| 커뮤니티 게시글 본문 | `공공 관광 데이터로 후보지를 찾고 AI 일정 초안을 만들어 본 시연용 게시글입니다.` |
| 댓글 | `일정 흐름이 보기 좋습니다.` |

지역 특화 제출을 선택하지 않았다면 특정 지역명을 과하게 강조하지 않는다. 특정 지역 특화로 전환할 경우 `docs/23-regional-specialization-strategy.md`의 조건에 맞춰 비서울 지역명과 기능 근거를 일치시킨다.

## 세팅 순서

| 2 | 여행지 탐색 화면에서 후보 장소 확인 | 여행지 카드가 로딩됨 | `docs/32-service-url-smoke-test-runbook.md` |
| 3 | 여행지 2~3개 찜 | 마이페이지 또는 찜 화면에서 확인 가능 | `docs/13-validation-report.md` |
| 4 | 폴더 1개 생성 | 폴더명이 시연용으로 보임 | `docs/13-validation-report.md` |
| 5 | 폴더에 장소 또는 메모 추가 | 빈 폴더가 아닌 상태 | `docs/13-validation-report.md` |
| 6 | AI Planner에서 일정 1개 생성 | 생성 결과 또는 저장된 일정 확인 가능 | `docs/13-validation-report.md` |
| 7 | 커뮤니티 게시글 1개 작성 | 목록 또는 상세에서 게시글 확인 가능 | `docs/13-validation-report.md` |
| 8 | 댓글 또는 좋아요 흐름 확인 | 상호작용 UI 확인 가능 | `docs/13-validation-report.md` |
| 9 | 로그아웃 후 재로그인 | 데이터가 유지되는지 확인 | `docs/19-test-account-verification.md` |
| 10 | 캡처 후보 확보 | `SC-04`, `SC-05`, `SC-06` 후보 생성 | `docs/31-submission-screenshot-plan.md` |

## 화면 캡처 전 점검

| 점검 항목 | 기준 |
|---|---|
| 찜·폴더 화면 | 최소 1개 이상의 저장 데이터가 보인다. |
| AI 일정 화면 | 생성 결과, 날짜별 코스, 저장된 일정 중 하나가 보인다. |
| 커뮤니티 화면 | 게시글 목록 또는 상세 화면이 비어 있지 않다. |
| 로그인 상태 | 개인 이메일이 화면 중앙에 크게 드러나지 않는다. |
| 오류 상태 | 오류 토스트, 무한 로딩, 빈 결과만 보이는 화면은 사용하지 않는다. |
| 시연 데이터 문구 | 공모전 시연용임이 자연스럽고 개인정보가 없다. |

## 테스트 데이터 실패 대응

| 상황 | 대응 |
|---|---|
| 찜 버튼이 동작하지 않음 | 로그인 상태와 Firebase Rules 오류를 확인하고, `docs/13-validation-report.md`에 실패로 기록한다. |
| 폴더 생성 실패 | 사용자 소유 데이터 경로와 권한을 확인한다. |
| AI 일정 생성 실패 | Gemini timeout, 429, JSON 실패 여부를 구분하고, 기존 저장 일정이 있으면 저장 화면을 캡처 후보로 사용한다. |
| 커뮤니티 작성 실패 | 게시글 작성 권한과 필수 입력값을 확인한다. |
| 재로그인 후 데이터가 사라짐 | 저장 위치가 테스트 계정 UID 하위인지 확인한다. |
| 화면에 개인정보가 보임 | 캡처를 폐기하고 다른 화면 또는 크롭 후보를 사용한다. |

## 제출 전 판정

| 판정 | 조건 |
|---|---|
| 통과 | DD-01~DD-05가 준비되고, `SC-04`, `SC-05`, `SC-06` 캡처 후보를 확보했다. |
| 부분 통과 | 로그인과 일부 데이터는 준비됐지만 AI 일정 또는 커뮤니티 데이터 중 하나가 부족하다. |
| 실패 | 테스트 계정 로그인 또는 사용자 소유 데이터 저장이 불가능하다. |

## 현재 상태

현재 문서 기준으로 테스트 계정 생성·검증 절차는 정의되어 있으나, 실제 제출용 계정 생성과 시연 데이터 세팅은 아직 미완료다. 따라서 기능설명서 최종 캡처 작업 전에는 이 문서의 DD-01~DD-06 준비 상태를 먼저 확인해야 한다.
