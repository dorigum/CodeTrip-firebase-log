# MVP 안정화·심사 제출 준비 스프린트 회고

- **기간**: 2026-08-16 ~ 2026-09-18
- **목적**: CodeTrip의 핵심 사용자 흐름을 배포 가능한 MVP로 안정화하고, 공모전 1차 심사 자료와 운영 검증 근거를 정리합니다.
- **범위**: 공공 관광데이터 탐색, 위시리스트·폴더, AI 일정, 커뮤니티, 인증·개인 데이터, 품질 자동화, 제출 문서입니다.

## 2. 잘된 점

### 2.1 기능을 개별 화면이 아닌 하나의 여행 준비 흐름으로 완성했습니다

여행지·축제 탐색, 상세 정보와 지도·날씨 확인, 찜·폴더 분류, AI 일정 생성·저장, 커뮤니티 공유와 활동 확인까지를 연결했습니다. 특히 저장한 장소와 여행 조건을 AI 생성에 다시 반영하고, 생성 결과를 폴더·메모·체크리스트와 함께 관리하도록 설계해 단순 추천 화면에서 끝나지 않도록 했습니다.

### 2.2 AI 결과의 출처·지역·저장 조건을 검증 대상으로 다뤘습니다

AI 일정은 JSON 구조로 관리하고 TourAPI 검증 장소와 AI 보조 추천 장소를 구분합니다. 폴더 기반 생성에서는 저장 장소 주소와 최근 생성 컨텍스트를 이용해 대표 지역·필수 방문 권역·동행·인원·여행 기간을 복원하고, 다른 지역 장소가 섞이지 않도록 차단했습니다. 저장 장소가 없는 기존 AI 코스 폴더도 최근 저장 일정의 장소·지역 조건을 복원해 재생성할 수 있도록 보완했습니다.

### 2.3 배포 후 발견한 문제를 운영 검증으로 되돌렸습니다

체크리스트 중복, 폴더 장소 수 불일치, 데스크톱 페이지네이션의 빈 카드·스크롤 이동, 많은 폴더의 노출 방식, 알림 문구, 회원 탈퇴 데이터 정리 등은 배포 환경 점검에서 발견했습니다. 각 문제를 재현 조건과 함께 수정하고, 날짜별 개발 기록·트러블슈팅·검증 보고서에 근거를 남겼습니다.

### 2.4 품질 검증을 CI와 운영 점검으로 이중화했습니다

GitHub Actions에서 프런트엔드 lint·build, Functions 테스트, Firebase Database Rules 테스트, 공개 라우팅 E2E를 실행합니다. CI의 preview 포트·Firebase 초기화 설정 차이로 발생한 실패도 재현해 고쳤습니다. 배포 환경에서는 이메일·Google 회원의 탈퇴, 폴더·AI 일정·체크리스트 연동, 반응형 화면, 외부 API 실패 안내를 별도로 확인했습니다.

## 3. 어려웠던 점과 배운 점

| 상황 | 원인 | 대응과 배운 점 |
|---|---|---|
| 폴더 기반 AI 코스에 다른 지역·기본 조건이 섞일 수 있었음 | 폴더의 장소·저장 컨텍스트·AI 응답 검증이 서로 다른 시점에 적용됨 | 주소 우선 지역 판단, 생성 컨텍스트 복원, 서버 저장 직전 검증을 함께 적용했습니다. AI 기능은 프롬프트 품질만이 아니라 입력·출력·저장 경계의 일관성이 중요합니다. |
| 저장 장소가 없는 기존 AI 코스를 재생성할 수 없었음 | 위시리스트 장소만 후보로 판단해 기본 지역 서울이 읽기 전용으로 남음 | 최근 저장 플랜의 `days.items`와 `generationContext`를 대체 후보로 사용하되, 실제 저장 장소가 있으면 이를 우선하도록 했습니다. 레거시 데이터 경로도 사용자 흐름으로 점검해야 합니다. |
| CI E2E가 로컬에서는 통과하지만 PR에서 실패함 | Vite preview 포트, Firebase 초기화 값, 요소 선택자에서 로컬과 CI의 전제가 달랐음 | 빌드 산출물 preview를 기준으로 포트와 대기 시간을 고정하고, 공개 경로에만 형식상 유효한 CI Firebase 값을 주입했습니다. 자동화는 개발 서버가 아닌 배포에 가까운 조건에서 검증해야 합니다. |
| 운영 테스트의 범위가 넓어졌지만 장기 지표가 부족함 | 기능 안정화와 제출 준비에 집중해 실제 사용량·성능 수집 기간이 짧음 | 측정되지 않은 수치를 성과로 주장하지 않고, 다음 스프린트에서 RTDB 사용량·캐시·AI 성공률·외부 API 오류를 릴리스별로 관찰하기로 했습니다. |

## 4. 검증 결과와 지표

### 확인된 결과

- `npm run lint` 경고 0건을 확인했습니다.
- 프로덕션 `npm run build`를 통과했고, 라우트 단위 코드 스플리팅 후 단일 초기 JavaScript 번들을 공통 엔트리·Firebase·페이지 청크로 분리했습니다.
- Firebase Database Rules Emulator 권한 테스트 15건, 공개 라우팅 Playwright E2E 3건을 CI에 포함했습니다.
- 배포 환경에서 이메일·Google 회원의 재인증 탈퇴와 Realtime Database 개인 데이터 정리를 확인했습니다.
- 외부 API 오류에서 TourAPI 저장 차단, 날씨·위치명 fallback, Gemini 오류 안내를 테스트·수동 점검 범위에 포함했습니다.

### 아직 측정하지 않은 항목

- 실제 사용자 수, 재방문율, 저장·AI 코스 생성 전환율
- 저속 네트워크 환경의 LCP·전송량과 장기 캐시 적중률
- 외부 API 장애 빈도·복구 시간·AI 생성 성공률의 누적값

위 항목은 수치가 없으므로 이번 스프린트 성과로 과장하지 않습니다. 측정 방법과 기록 위치는 [KPI·평가 지표](../09-metrics.md), [API 캐시 측정표](../38-cache-measurement-sheet.md), [검증 보고서](../13-validation-report.md)를 기준으로 이어갑니다.
