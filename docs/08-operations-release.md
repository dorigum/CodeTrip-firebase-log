# 운영·릴리스

## 배포 절차

1. 변경 범위와 관련 문서 확인
2. `npm run lint` 및 `npm run build`
3. 핵심 시나리오와 권한 점검
4. `dist` 생성 결과 확인
5. Firebase Hosting 배포
6. 공개 URL에서 smoke test
7. 릴리스 기록과 알려진 이슈 작성

## 장애 대응

외부 API 오류는 사용자 안내·재시도·캐시 fallback을 사용한다. 인증·DB 오류는 영향을 받는 기능을 격리하고, Firebase 콘솔 로그와 재현 조건을 기록한다. AI 실패는 실패 원인을 노출하지 않고 재시도와 기본 추천 경로를 제공한다.

## 변경 관리

기술·기획 선택은 `decision-log/`에 배경, 선택지, 결정, 영향, 재검토 조건을 기록한다. 스프린트 종료 시 `retrospectives/`에 잘된 점, 문제, 다음 액션을 남긴다.
