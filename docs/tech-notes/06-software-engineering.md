# 소프트웨어 공학

## 핵심 주제

- 문제 정의와 요구사항
- MVP, MoSCoW 우선순위
- 사용자 스토리와 인수 기준
- 경량 애자일·스프린트·회고
- WBS·릴리스·변경 관리
- 기술부채와 의사결정 기록

## CodeTrip 적용 위치

현재 프로젝트는 기능을 빠르게 반복해 온 흐름이므로, 1~2주 단위 스프린트와 문서 갱신을 결합하는 방식이 적합합니다. 기획·요구사항·아키텍처·품질·AI 분석의 기초 표준은 `docs/01`~`docs/11`에서 관리하고, 기술 부채·검증·백로그·심사 제출 등 운영 기준은 `docs/12` 이후 문서에서 확장 관리합니다. 선택의 배경은 `decision-log`에 남깁니다.
