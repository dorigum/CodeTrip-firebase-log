# 심사 시연 시나리오

이 문서는 CodeTrip을 심사 가능한 MVP로 설명하기 위한 시연 흐름을 정의한다. 시연의 목표는 모든 기능을 길게 보여주는 것이 아니라, 핵심 사용자 여정과 기술 선택의 이유, 품질·보안·운영 기준을 짧은 시간 안에 증빙하는 것이다.

## 시연 목표

- 사용자가 여행지를 발견하고 저장한 뒤 AI 일정으로 확장하는 핵심 가치를 보여준다.
- Firebase 기반 인증·개인 데이터 분리·커뮤니티 권한 구조를 설명한다.
- TourAPI, Open-Meteo, Kakao Maps, Gemini API가 어떤 역할로 연결되는지 보여준다.
- 오류·빈 상태·외부 API 실패·AI 실패를 고려한 MVP 품질 기준을 설명한다.
- 미완료 항목과 기술 부채를 숨기지 않고 다음 백로그로 연결한다.

## 권장 시연 시간

| 구간 | 시간 | 목적 |
|---|---:|---|
| 서비스 소개 | 1분 | 문제 정의와 MVP 범위 설명 |
| 여행지 탐색·상세 | 3분 | 핵심 데이터 탐색 흐름 증명 |
| 로그인·찜·폴더 | 3분 | 개인화와 데이터 권한 흐름 증명 |
| AI 일정 생성 | 4분 | Gemini 하네스와 TourAPI 검증 가치 설명 |
| 마이페이지·커뮤니티 | 2분 | 저장 결과와 사용자 참여 흐름 설명 |
| 품질·보안·운영 | 2분 | 검증 기준, 기술 부채, 다음 계획 설명 |

총 15분을 기준으로 하며, 시간이 짧으면 커뮤니티와 운영 설명을 압축한다.

## 발표 멘트 초안

### 1. 서비스 소개

CodeTrip은 여행지를 탐색하는 기능에서 끝나지 않고, 사용자가 관심 여행지를 저장하고 그 데이터를 바탕으로 AI 여행 일정 초안을 생성하는 MVP입니다. 핵심 범위는 탐색, 상세 조회, 인증, 찜·폴더, AI 일정 생성, 커뮤니티입니다. 예약, 결제, 관리자 기능은 이번 MVP 범위에서 제외했습니다.

### 2. 기술 구조 설명

프론트엔드는 React, Vite, Tailwind CSS, Zustand로 구성되어 있고, Firebase Authentication, Realtime Database, Hosting을 사용합니다. 여행지 데이터는 TourAPI, 날씨와 위치 보조 정보는 Open-Meteo와 Nominatim, 지도는 Kakao Maps, 일정 생성은 Gemini API와 연결됩니다.

### 3. AI 기능 설명

AI 일정 생성은 단순히 Gemini API를 호출하는 기능이 아니라, 입력 조건을 구성하고 JSON 응답을 검증한 뒤 CodeTrip의 저장 구조에 맞게 정규화하는 하네스 관점으로 설계했습니다. 검증된 관광공사 장소와 AI가 보조로 추천한 장소를 구분하여 저장하는 것이 핵심입니다.

### 4. 품질과 한계 설명

현재 프로젝트는 문서 기준, 검증 보고서, 기술 부채 등록부, 백로그를 통해 완료된 항목과 미완료 항목을 분리해서 관리합니다. 예를 들어 번들 크기 경고, Gemini API 키의 서버 프록시 이전, 정량 성능 측정값 부족은 기술 부채로 등록되어 있으며, 해결 기준과 증빙 위치를 따로 관리합니다.

## 실패 시 대체 시연

| 실패 상황 | 대체 방식 | 설명 포인트 |
|---|---|---|
| 외부 여행 API 지연 | 캐시 정책과 stale fallback 문서 설명 | 외부 의존성 실패를 전제로 설계한다. |
| 지도 또는 날씨 표시 실패 | 상세 화면의 오류·대체 안내 상태 설명 | 전체 화면 중단 대신 부분 실패로 격리한다. |
| Gemini API 실패 | AI timeout, 429, JSON 실패 처리 기준 설명 | 실패 케이스도 품질 게이트에 포함한다. |
| 로그인 문제 | 보호 라우트와 Firebase Auth 구조 설명 | 인증 상태에 따라 접근을 제한한다. |
| 데이터 쓰기 실패 | Firebase Rules와 검증 보고서 연결 | 권한 문제는 검증 시나리오로 관리한다. |

| MVP 이후 계획은 무엇인가? | Rules 검증, 성능 기준선 측정, 코드 스플리팅, AI 프록시 이전, E2E 테스트 도입 순서로 진행한다. | `docs/14-backlog.md` |

## 완료 기준

- 시연자가 15분 안에 대표 흐름을 끊기지 않고 설명할 수 있다.
- 실패 상황이 발생해도 대체 설명과 연결 문서가 준비되어 있다.
- 구현된 항목, 계획된 항목, 측정되지 않은 항목을 구분해 말할 수 있다.
- 공개 시연 전 Gemini API 키 보호 조건을 충족하거나, 임시 시연 시 호출량 제한·키 교체·사용량 모니터링 절차를 준비한다.
- 심사자가 서비스 목적, 핵심 기능, 기술 구조, 한계, 다음 계획을 이해할 수 있다.
