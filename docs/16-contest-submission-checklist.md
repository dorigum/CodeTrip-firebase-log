# 2026 관광데이터 활용 공모전 1차 심사 제출 준비

이 문서는 2026 관광데이터 활용 공모전 웹·앱 개발 부문 1차 심사 자료 제출 항목에 맞춰 CodeTrip의 제출 준비 상태를 관리한다. 실제 인증키, 비밀번호, 개인 이메일 등 민감정보는 이 저장소에 기록하지 않는다.

현재 기능설명서 초안의 제출 조건 충족 여부와 남은 갭은 `docs/18-submission-gap-analysis.md`에서 별도로 관리한다. 심사용 테스트 계정 생성과 로그인 후 기능 검증 절차는 `docs/19-test-account-verification.md`, 한국관광공사 OpenAPI 제출 정보 검증은 `docs/20-openapi-submission-verification.md`를 따른다.

## 테스트 계정 준비 기준

로그인이 필요한 기능이 있으므로, 심사용 테스트 계정은 미리 생성한다. 개인 계정 제출은 피하고, 공지의 지정 형식을 따른다.

| 방식 | 제출 가능 여부 | CodeTrip 권장 |
|---|---|---|
| 로그인 불필요 | 일부 탐색 기능만 가능 | 비권장 |
| SNS 연동 로그인 | 현재 별도 확인 필요 | 미확인 |
| 별도 계정 로그인 | Firebase Auth 기반으로 준비 가능 | 권장 |

권장 테스트 계정 형식은 이메일 계정 방식이다. 실제 계정 ID와 비밀번호는 제출 페이지에만 입력하고 문서·커밋에는 남기지 않는다.

| 최종 제출 PDF | 5페이지 정리본 초안 존재 | 팀명·캡처 교체 후 PDF 변환, 5페이지 이하·12포인트 이상·10MB 미만·정상 열람 확인 | 제출 첨부파일, `docs/17-submission-artifact-manifest.md` |

## 로그인 후 화면 캡처 교체 기준

현재 기능설명서 정리본은 비로그인 상태에서 확보 가능한 홈, 탐색, 축제, 로그인, AI 접근 제한 화면을 사용한다. 최종 제출 전 테스트 계정이 준비되면 아래 우선순위로 상세 이미지를 교체한다.

| 우선순위 | 교체 대상 화면 | 교체 이유 | 검증 기준 |
|---|---|---|---|
| 1 | AI 일정 생성 결과 화면 | 서비스 차별성과 AI 활용 근거를 가장 직접적으로 보여준다. | 테스트 계정 로그인 → AI 조건 입력 → 일정 초안 생성 또는 저장 화면 확인 |
| 2 | 마이페이지 또는 찜/폴더 화면 | 개인화 여행 계획 관리 기능을 증명한다. | 로그인 → 찜/폴더 저장 데이터 확인 → 개인정보 노출 여부 점검 |
| 3 | 커뮤니티 게시글 또는 활동 화면 | 사용자 참여 흐름과 서비스 완성도를 보강한다. | 로그인 → 게시글 목록·상세 또는 댓글/좋아요 흐름 확인 |
| 4 | 여행지 상세 화면 | TourAPI 상세·이미지·지도·날씨 연계 근거를 보강한다. | 상세 페이지 로딩 완료 후 API 오류/로딩 상태가 아닌 화면 캡처 |

## 주의 사항

- 기능설명서는 반드시 제공된 PPTX 양식을 사용하고, 제출 시 PDF로 변환한다.
- 한국관광공사 OpenAPI 인증키는 제출 페이지에만 입력하고 저장소에는 기록하지 않는다.
- 테스트 계정은 개인 계정이 아닌 제출용 전용 계정을 사용한다.
- 지역 특화 가점을 노릴 경우 서울은 제외되므로, 전국 서비스로 제출할지 특정 지역 특화로 조정할지 먼저 결정한다.
- 측정되지 않은 성능 수치나 검증되지 않은 완료율은 기능설명서에 정량 성과로 작성하지 않는다.
- 1차 심사 일정과 서류 제출 기간은 공식 공고와 대상자별 별도 안내가 다를 수 있으므로 제출 페이지에서 최종 확인한다.
- 제공 양식의 필수 항목을 임의로 삭제하거나 변경하지 않고, PDF 변환 후 페이지 수, 글자 크기, 파일 용량, 정상 열람 여부를 확인한다.
