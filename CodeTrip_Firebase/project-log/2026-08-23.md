# 2026-08-23 작업 로그

> 이 문서는 PR #28 `feature/trip-date-planning` 브랜치에서 CodeRabbit 피드백을 반영한 AI 여행 일정 날짜 안정화 작업과 제출 자료 누락 점검 결과를 기록합니다.

## 1. 작업 개요

AI 여행 계획 날짜 입력 기능과 마이페이지 폴더 일정 수정 UX를 추가한 뒤, CodeRabbit 리뷰에서 지적된 날짜 정규화와 비동기 폴더 선택 경합 가능성을 보완했습니다. 이번 작업은 새로운 화면이나 제출 항목을 추가하기보다는, 이미 구현된 AI 일정 날짜 기능이 사용자 입력과 폴더 기반 생성 흐름에서 일관되게 동작하도록 안정화하는 작업입니다.

공모전 1차 제출 자료 관점에서는 기능설명서, OpenAPI 활용 목록, 테스트 계정, 최종 PDF 검증처럼 제출 페이지와 최종 산출물에서 직접 확인해야 하는 항목이 계속 남아 있습니다. 오늘의 코드 변경은 AI 일정 생성 기능의 내부 안정성 보강이므로, 기능설명서 필수 페이지 구조를 새로 늘리지는 않습니다. 다만 기능설명서의 AI 일정 생성 설명에는 “여행 날짜를 입력하거나 폴더 일정과 연계해 저장할 수 있다”는 문구를 반영하면 기능 완성도 설명에 도움이 됩니다.

## 2. AI 플래너 폴더 일정 정규화 보완

폴더 기반 AI 일정 생성에서 선택한 폴더의 `start_date`, `end_date`, `durationDays`가 서로 다른 기준으로 처리될 수 있는 경로를 보완했습니다.

- 시작일과 종료일이 모두 없는 폴더는 기존 기본값을 유지하고 조정 안내를 표시하지 않습니다.
- 시작일이 없거나 잘못된 날짜인 경우에는 날짜 입력값을 빈 값으로 되돌리고, 일정이 조정되었다는 안내를 표시합니다.
- 종료일이 없거나 잘못된 날짜인 경우에는 종료일을 시작일과 같은 날짜로 맞추고 1일 일정으로 정규화합니다.
- 시작일보다 종료일이 빠른 경우에는 1일 일정으로 보정합니다.
- 5일을 초과하는 폴더 일정은 AI 생성 가능 범위인 최대 5일로 잘라서 `durationDays`, `travelStartDate`, `travelEndDate`를 같은 범위로 맞춥니다.
- 조정 안내 문구는 “최대 5일 초과”만 설명하지 않고, 누락·무효·역전·초과 날짜를 모두 포괄하도록 “유효한 1~5일 범위” 기준으로 변경했습니다.

이 보완으로 화면에 표시되는 여행 일수와 실제 생성 전 검증에 사용되는 날짜 범위가 어긋나는 문제를 줄였습니다.

## 3. 비동기 폴더 선택 최신성 검증 보완

폴더 기반 생성 모드에서 선택한 폴더의 장소 주소가 부족하면 `hydratePlaceAddresses()`가 비동기로 상세 주소를 보강합니다. 이 작업이 끝나기 전에 사용자가 지역명, 날짜, 생성 조건을 직접 수정하거나 생성 요청을 시작하면, 늦게 도착한 폴더 보강 결과가 현재 입력 상태를 덮어쓸 수 있었습니다.

이를 방지하기 위해 폴더 선택 시점에 아래 값을 함께 저장하고, 비동기 주소 보강 완료 후 두 값이 모두 최신일 때만 `regionName`을 자동 반영하도록 변경했습니다.

- `folderSelectionRequestRef.current`
- `plannerRevisionRef.current`

따라서 사용자가 폴더 주소 보강을 기다리는 동안 입력값을 변경하거나 생성 흐름을 시작하면, 이전 폴더 선택 결과는 더 이상 지역명을 덮어쓰지 않습니다. 이 변경은 진행 중인 생성 결과가 불필요하게 폐기되는 상황도 줄입니다.

7. 동일 서비스 중복 출품 없음, 웹·앱 개발 부문 양식 일치, 제출 마감 전 수정 가능 시간을 확인합니다.
