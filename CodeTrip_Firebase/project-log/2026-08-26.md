# 2026-08-26 CodeTrip 개발 로그

## 1. PR #29 CodeRabbit 추가 피드백 반영

TourAPI 신규 여행지 알림, Firebase Storage 이미지 업로드, 모바일·반응형 UI 개선 작업 이후 CodeRabbit이 추가로 지적한 정합성 항목을 확인했습니다. 이번 작업은 신규 기능을 크게 확장하기보다는 기존 구현이 다양한 실행 환경에서 안정적으로 동작하도록 보완하는 데 집중했습니다.

### 1.1 Home 축제 날짜 계산 기준 보정

- 기존 `getTodayKey()`는 브라우저 로컬 시간을 기준으로 `YYYYMMDD` 날짜 키를 생성했습니다.
- TourAPI의 축제 일정은 한국 날짜 기준으로 해석하는 것이 자연스럽기 때문에 `Asia/Seoul` 타임존 기준으로 날짜 키를 생성하도록 변경했습니다.
- 해외 또는 다른 타임존 브라우저에서 접속해도 오늘 시작하는 축제가 `D-1`처럼 잘못 표시되지 않도록 보정했습니다.

### 1.2 여행지 탐색 반응형 카드 그리드 보완

- 모바일에서는 한 줄 2개 카드 구성을 유지합니다.
- 데스크톱 폭에서는 `lg` 이상 3열, `xl` 이상 4열로 확장되도록 보완했습니다.
- 모바일 UI 조정 이후 데스크톱에서 카드가 2열에 고정되어 넓은 화면을 충분히 활용하지 못하는 문제를 줄였습니다.

### 1.3 여행지 탐색 API 요청 최신성 보장

- 화면 크기 변경, 필터 변경, 페이지 변경이 짧은 시간 안에 겹치면 이전 요청이 나중에 완료되어 최신 화면 상태를 덮어쓸 수 있었습니다.
- `useExploreStore`에 요청 순번을 추가해 최신 요청의 응답만 `posts`, `totalCount`, `loading`, `fetchError` 상태에 반영하도록 수정했습니다.
- `itemsPerPage`가 바뀌는 경우 저장된 스크롤 값뿐 아니라 실제 `#main-scroll` DOM 스크롤 위치도 0으로 초기화하도록 보완했습니다.

### 1.4 내 활동 최근 본 여행지 모바일 토글 기준 정렬

- `최근 본 여행지`의 `전체 보기` 버튼이 표시되는 breakpoint와 목록 접힘 기준이 서로 달라 일부 화면 폭에서 버튼을 눌러도 표시 결과가 바뀌지 않는 문제가 생길 수 있었습니다.
- 버튼 표시 기준을 목록 접힘 기준과 맞춰 모바일에서만 동작하도록 수정했습니다.

## 2. TourAPI 신규 여행지 알림 운영 확인 메모

배포 사이트에서 로그인했을 때 신규 여행지 알림이 뜨지 않는 상태를 확인했습니다. Firebase Functions 화면에서는 `syncTourApiUpdates`의 최근 24시간 요청 수가 0으로 표시되어, 현재 상태만으로는 “신규 관광공사 데이터가 없다”고 단정하기 어렵습니다.

### 2.1 판단 기준

- `syncTourApiUpdates` 요청 수가 0이면 스케줄 함수가 아직 실행되지 않았거나, 실행 로그가 집계되기 전 상태로 봅니다.
- 함수가 실행되었고 신규 데이터가 없다면 Realtime Database의 `tourApiUpdates/state`에 마지막 확인 시각과 신규 항목 수 0이 기록되어야 합니다.
- 신규 데이터가 감지되면 `tourApiUpdates/items`에 항목이 생성되고, 로그인 사용자의 Header 알림 목록에 `[신규 여행지]` 알림이 표시되어야 합니다.

### 2.2 후속 확인

- Firebase Console의 Functions 로그에서 `syncTourApiUpdates` 실행 여부를 확인합니다.
- Google Cloud Scheduler에서 해당 스케줄 작업의 실행 이력을 확인합니다.
- 첫 실행 이후 Realtime Database의 `tourApiUpdates/state` 생성 여부를 확인합니다.
- 필요하면 수동 실행 또는 스케줄 주기 조정으로 기능 검증 시간을 단축합니다.

- 위 항목은 아직 배포 사이트 기준으로 수행하지 않았으므로 `후속 확인 필요` 상태로 분리합니다. 실제 확인 후 수행자, 환경, 확인 흐름, 결과 또는 실패 지점을 `docs/13-validation-report.md` 기준에 맞춰 갱신합니다.

## 4. 데스크톱 상단 공통 레이아웃 정리

데스크톱 화면에서 페이지별 제목 시작 위치, 상단 여백, 본문 최대 폭이 조금씩 달라 보이는 문제를 정리했습니다. `PageHeader` 컴포넌트 자체는 이미 공통화되어 있었기 때문에, 이번 작업은 각 페이지의 외부 컨테이너 기준을 맞추는 방식으로 진행했습니다.

### 4.1 정리 대상

- 여행지 탐색: `src/pages/Explore.jsx`
- 축제 및 행사: `src/pages/Festivals.jsx`
- AI 여행 플래너: `src/pages/AiPlanner.jsx`
- 여행 게시판: `src/pages/Board.jsx`
- 게시글 작성/수정: `src/pages/BoardWrite.jsx`
- 내 활동: `src/pages/MyActivity.jsx`
- 사용자 정보 수정: `src/pages/Settings.jsx`
- 태그 기반 여행지 검색: `src/pages/TravelTagSearch.jsx`

### 4.2 적용 기준

- 데스크톱 기준 최대 폭을 `max-w-[1600px]`로 맞췄습니다.
- 공통 좌우 여백은 `px-4 sm:px-6 lg:px-8` 흐름으로 정리했습니다.
- 공통 상단 여백은 `py-8 lg:py-12` 흐름으로 정리했습니다.
- 모바일 하단 내비게이션과 겹치지 않아야 하는 화면은 기존 `pb-20`, `pb-24` 계열 여백을 유지했습니다.
- `MyPage`는 폴더 패널과 본문이 결합된 특수 레이아웃이므로, 이번 공통화 범위에서는 제외하고 별도 폴리싱 대상으로 분리했습니다.

### 4.3 검증 결과

- `npm run lint`를 실행해 통과를 확인했습니다.
  - 기존 React Hook warning 11개는 유지됩니다.
- `npm run build`를 실행해 프로덕션 빌드 성공을 확인했습니다.
  - `dist/assets/index-CzEfJoTw.js` 1,096.22kB, gzip 310.71kB로 기존 500kB 초과 청크 경고는 유지됩니다.
  - Vite plugin timing 경고도 기존 기술 부채로 유지됩니다.

### 4.4 후속 확인

- 배포 전후 데스크톱 1440px 이상 화면에서 주요 페이지의 제목 시작 위치와 상단 간격을 육안 확인합니다.
- 게시판, 사용자 정보 수정, 내 활동 화면은 본문 폭이 넓어진 상태가 실제 사용성에 맞는지 확인하고, 필요하면 제목 영역과 본문 영역의 폭 기준을 분리합니다.

## 5. PR #29 CodeRabbit 후속 피드백 반영

CodeRabbit이 2026-08-26에 추가로 남긴 피드백 3건을 확인하고, 즉시 반영 가능한 항목을 수정했습니다. 이번 보완은 배포 후 수동 확인이 필요한 항목과 코드·정적 검증으로 확인 가능한 항목을 분리하는 데 중점을 두었습니다.

### 5.1 Home 축제 날짜 파싱 유효성 보강

- `Home.jsx` 내부에 있던 날짜 키 계산 로직을 `src/utils/dateKey.js`로 분리했습니다.
- `parseDateKey()`가 `20260231`, `20261301`, `20260001`처럼 JavaScript `Date` 객체가 자동 보정할 수 있는 잘못된 날짜를 `null`로 반환하도록 변경했습니다.
- 생성된 `Date`의 연·월·일이 입력값과 일치하는지 비교해 유효하지 않은 달력 날짜가 Home 축제 D-day 배지와 정렬 계산에 사용되지 않도록 했습니다.
- `src/utils/dateKey.test.js`를 추가하고 `npm run test:date-key` 스크립트로 날짜 경계값을 검증할 수 있게 했습니다.

### 5.2 검증 문서 추적성 보완

## 6. 여행지 탐색 데스크톱 카드 그리드 보정

모바일 웹 카드 밀도를 줄이는 과정에서 데스크톱 여행지 탐색 페이지의 카드 배열이 `xl` 화면부터 4열로 확장되어, 한 페이지에 6개가 표시되는 경우 마지막 줄이 `4 + 2` 형태로 떨어지고 오른쪽 두 칸이 비어 보이는 문제가 확인되었습니다.

### 6.1 수정 방향

- 여행지 탐색 카드 그리드는 모바일에서 2열을 유지합니다.
- 데스크톱 일반 화면에서는 3열을 기본으로 사용해 6개 카드가 `3 + 3`으로 균형 있게 보이도록 조정했습니다.
- 매우 넓은 화면에서만 4열로 확장되도록 `xl:grid-cols-4`를 `2xl:grid-cols-4`로 변경했습니다.

### 6.2 후속 확인 필요

- 배포 후 데스크톱 1440px 내외 화면에서 여행지 탐색 페이지의 카드가 `3 + 3` 형태로 표시되는지 확인해야 합니다.
- 2XL 이상 초대형 화면에서는 4열 확장이 의도대로 동작하는지 확인해야 합니다.
