# 2026-09-04 작업 로그

## 1. 새로고침 시 비회원 홈 화면이 일시적으로 노출되는 인증 복원 깜빡임 보정

### 문제

로그인한 사용자가 홈에서 새로고침하면 Firebase Authentication의 `onAuthStateChanged()`가 세션을 복원하기 전에 홈이 `isLoggedIn: false`를 기준으로 비회원 화면을 먼저 렌더링했습니다. 인증 콜백이 완료된 뒤 회원 홈으로 다시 전환되어 화면이 순간적으로 바뀌었습니다.

### 원인

인증 스토어는 초기 상태를 `isLoading: true`로 두고 Firebase 세션 복원을 비동기로 처리하지만, `Home`은 `isLoggedIn`만 확인해 인증 초기화 완료 전 상태를 비회원으로 해석했습니다. 이 구간에서 홈 데이터 초기화와 위시리스트 요청도 비회원 상태 기준으로 시작될 수 있었습니다.

### 처리

- `Home`에서 인증 스토어의 `isLoading`을 `isAuthLoading`으로 받아 인증 상태가 확정될 때까지 공통 세션 복원 로딩 화면을 표시합니다.
- 인증 초기화 중에는 홈 데이터 초기화·위치 기반 조회와 위시리스트 초기화를 보류합니다.
- Header·Sidebar는 기존의 인증 로딩 스켈레톤을 유지해, 홈·Header·Sidebar가 같은 인증 상태 기준으로 렌더링됩니다.

### 확인 기준

- 로그인 상태에서 새로고침해도 비회원 홈이 먼저 노출되지 않고 세션 복원 로딩 뒤 회원 홈이 표시되어야 합니다.
- 실제 비로그인 사용자는 인증 초기화 완료 후 기존 비회원 홈을 정상적으로 확인할 수 있어야 합니다.
- 로그인·로그아웃과 Google OAuth 신규 가입·기존 계정 안내 흐름은 기존 동작을 유지해야 합니다.

## 2. Google-only 계정 비밀번호 변경 차단

### 문제

Google 계정으로 로그인한 사용자의 설정 화면에도 이메일·비밀번호 계정용 변경 폼이 표시됐습니다. 이 폼은 `EmailAuthProvider` 재인증을 사용하므로 Google 비밀번호를 입력해도 `auth/wrong-password` 오류가 발생해 사용자가 혼란스러울 수 있었습니다.

### 처리

- 설정 화면은 Firebase `providerData`에 `password` 제공업체가 연결된 경우에만 비밀번호 변경 폼을 표시합니다.
- Google-only 계정에는 Google 계정 보안 설정에서 비밀번호를 관리한다는 안내를 표시합니다.
- `authApi.updatePassword()`도 `password` 제공업체 연결 여부를 재확인해 UI를 우회한 호출을 차단합니다.
- Firebase의 비밀번호 변경 API는 Google 계정 비밀번호를 변경할 수 없습니다. 과거 변경 성공 사례가 있다면 해당 Firebase 사용자에 이메일·비밀번호 제공업체도 연결되어 있었고, 변경된 값은 그 Firebase 이메일·비밀번호 자격 증명입니다.

### 확인 기준

- Google-only 계정에서는 변경 입력 필드·버튼이 노출되지 않고 안내만 표시되어야 합니다.
- 이메일·비밀번호 계정과 `password` 제공업체가 연결된 복수 제공업체 계정은 현재 비밀번호 확인 후 변경할 수 있어야 합니다.
