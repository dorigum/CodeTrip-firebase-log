## 위시리스트 삭제 완료 알림 구분

- 위시리스트 저장·추가는 초록색 성공 알림을 유지하고, 삭제 완료에는 휴지통 아이콘과 앰버 색상 전용 알림을 적용했다.
- 빨강은 요청 실패·오류 알림과 혼동될 수 있으므로 사용하지 않았다. 탐색·축제·여행지 상세·마이페이지의 위시리스트 삭제 흐름에 동일하게 적용했다.

## 저장 장소 없는 폴더의 AI 코스 재생성 보완

- 일부 기존 AI 코스 폴더는 관광공사 여행지 위시리스트가 비어 있지만, 이미 저장된 AI 일정에는 장소·지역·동행 조건이 남아 있었습니다. 기존 플래너는 위시리스트만 후보로 판단해 `0 / 0`으로 표시하고, 기본 지역인 서울을 읽기 전용으로 잠가 재생성을 차단했습니다.
- 폴더에 실제 저장 여행지가 있으면 기존처럼 그 데이터를 최우선으로 사용합니다. 저장 여행지가 0개일 때에만 해당 폴더의 최근 저장 AI 코스에서 일정 장소와 생성 컨텍스트를 복원해 재생성 후보로 제시하도록 보완했습니다.
- 지역은 장소 주소를 우선하고, 주소가 없을 때는 저장된 AI 코스의 지역 조건을 사용합니다. 따라서 수원 코스처럼 기존 컨텍스트가 `경기`인 경우 서울 기본값으로 고정되지 않습니다.
- 폴더 선택 목록에는 `0 · 저장 코스 6`처럼 대체 가능한 장소 수를 표시하고, 목록 하단에는 기존 AI 코스 장소를 재생성 후보로 사용 중임을 안내합니다. 저장 장소와 기존 AI 코스 모두 없을 때만 기존의 생성 차단 안내가 유지됩니다.

## CI E2E 미리보기 서버 포트 고정

- PR #39의 `Quality checks` 실패 로그를 확인해, CI에서 `vite preview`가 기본 포트 `4173`으로 실행되는 동안 Playwright가 `5173`을 기다려 120초 후 시간 초과한 것을 확인했다.
- CI용 미리보기 명령에 `--port 5173`을 명시해 Playwright의 `baseURL`·대기 URL과 서버 포트를 일치시켰다.
- 동일한 `CI=true` 조건에서 E2E 라우팅 스모크 테스트를 다시 실행했다. 이 과정에서 화면의 시각 라벨을 접근성 레이블로 가정한 테스트가 실제 입력 요소를 찾지 못한 것을 확인해, 로그인 폼은 `email`·`password` input 타입을 기준으로 확인하도록 보완했다.
- 후속 실행에서 GitHub Actions에 Firebase 공개 설정이 없어 초기화 단계에서 화면이 렌더링되지 않는 것을 재현했다. 공개 라우팅 E2E에는 실제 운영 프로젝트를 연결하지 않고, 초기화에 필요한 형식상 유효한 CI 전용 더미 설정을 워크플로 환경 변수로 주입했다.
