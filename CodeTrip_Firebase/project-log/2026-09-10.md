# 2026-09-10 작업 기록

## AI 플래너 저장 조건 재생성 수동 검증

- 최초 확인은 저장 대상 폴더가 재생성 입력으로 전달되어 폴더 기반 모드가 강제되는 경로를 놓쳤으므로, 검증 완료 상태를 취소했다.
- 재생성은 저장 대상 폴더가 아닌 생성 컨텍스트의 원래 모드·폴더만 사용하도록 보완한다. 조건 기반으로 만들었던 코스는 입력 조건만 복원해, 조건 변경 뒤에는 기존 방문지 후보가 아닌 새 지역 후보로 다시 생성돼야 한다.
- 혼자 여행 조건인데 제목에 친구 여행이 표시된 AI 응답 사례도 확인해, 동행 조건 프롬프트를 보강하고 혼자 여행의 친구 동행 표현을 서버에서 정규화한다.
- 관련 회귀 문제의 원인·수정 방법·확인 기준은 `TROUBLESHOOTING.md` 77번 항목에 기록한다.

## AI 플래너 동행·인원 조건 정합성

- 여행 우선순위는 번호를 매기지 않는 다중 선택 조건임을 입력·판단 규칙 문서에 명확히 기록했다.
- 연인·가족·친구 여행에서 1명으로 생성될 수 있던 문제를 수정했다. 화면의 입력 최소값, 생성 직전 검증, Callable Function 입력 정규화가 모두 최소 2명을 적용한다.
- 혼자는 1명 고정을 유지하며, 동행 유형을 바꿀 때 기존 인원이 조건과 맞지 않으면 자동 보정하고 안내 메시지를 표시한다.

## AI 플래너 일정 시간 범위 검증

- 종료 시간이 시작 시간보다 이른 경우에도 코스가 생성되고, 모델이 종료 시간을 무시한 채 시작 시간부터 일정을 구성하던 문제를 확인했다.
- 종료 시간이 시작 시간보다 늦은지 화면 생성 전과 Callable Function에서 모두 검증한다. 잘못된 범위는 화면에 오류를 표시하고, 서버는 `invalid-argument`로 거절한다.

## 게시판 상호작용 알림 및 댓글 삭제 모달 통일

- 게시글 상세, 여행지 상세, 내 활동의 댓글·코멘트 삭제 확인을 브라우저 기본 경고창 대신 공통 `ConfirmModal`로 통일했다. 삭제 중 중복 요청을 막고 취소·닫기·키보드 포커스 동작을 공통 모달 정책으로 유지한다.
- 게시판 댓글 신규 작성과 게시글 좋아요 추가를 Functions RTDB 트리거로 감지해, 작성자가 아닌 사용자의 상호작용일 때만 게시글 작성자의 개인 알림에 기록한다.
- 알림 식별자는 댓글 또는 게시글·좋아요 사용자 조합으로 고정해 Function 재시도에도 같은 알림을 중복 생성하지 않으며, 작성자가 본인 게시글에 댓글·좋아요를 남긴 경우는 알림을 만들지 않는다.
- 게시글 댓글·좋아요 알림에는 대상 게시글 경로를 함께 저장해 Header에서 알림을 누르면 해당 글로 이동하게 했다. 게시판 댓글 좋아요도 댓글 작성자에게 알리고, 메시지에 댓글 본문 일부를 표시한다.

## Header 알림 삭제 제어 레이아웃 안정화

- 읽지 않은 알림의 상태 점과 hover 시 표시되는 삭제 버튼이 서로 다른 flex 항목을 차지해, 마우스를 올릴 때 텍스트 폭과 행 모양이 바뀌는 현상을 확인했다.
- 동일한 고정 크기 영역에 상태 점과 삭제 버튼을 겹쳐 배치하고 투명도만 전환해, hover 전후 알림 행의 폭과 줄바꿈이 변하지 않게 했다.

## 레거시·분리 좋아요 합산 처리

- 기존 콘텐츠의 `likeUserIds`와 보안 보완 뒤 새로 사용하는 `likes/{type}/{id}` 경로가 함께 존재할 때, 분리 경로 값만 우선해 기존 좋아요 수가 사라져 보이는 문제를 확인했다.
- 게시글·게시판 댓글·여행지 댓글 조회와 좋아요 토글 결과는 두 경로의 사용자 ID를 중복 없이 합산해, 기존 좋아요와 새 좋아요가 함께 표시되도록 보완했다.
- 좋아요 클릭 직후 임시로 증감시키던 수치는 기존·분리 경로 합산 결과가 도착할 때 다시 바뀔 수 있어, 요청 중 중복 클릭만 막고 서버의 최종 합산 수로 한 번만 갱신하도록 변경했다.
- 운영 반영 전에는 Firebase 프로젝트 ID를 지정해 `functions/scripts/migrateLegacyLikeUserIds.js`를 dry-run으로 확인한 뒤 `--commit`으로 세 대상(`boardPosts`, `boardComments`, `travelComments`)을 이전하고, 완료 건수와 원본 `likeUserIds` 제거 여부를 확인하도록 절차를 명시했다.
- 운영 데이터에서 게시글 4건, 게시판 댓글 3건을 실제 이전했으며, 완료 후 dry-run에서 레거시 `likeUserIds` 대상이 0건임을 확인했다. 여행지 댓글은 이전 대상이 없었다.

- 알림 삭제 버튼은 hover뿐 아니라 키보드 포커스가 알림 행 안에 있을 때도 표시되도록 `group-focus-within` 상태를 추가했다.
- 포커스 상태에서는 읽지 않음 점을 숨기고, 삭제 버튼에는 포커스 윤곽을 표시해 마우스 사용 시와 동일한 고정 레이아웃 및 접근성을 유지한다.

## 회원 이름 보장 및 인증 버튼 배치

- 일반 회원가입에서는 공백만 입력한 이름을 생성 전에 차단하고, 프로필 수정에서도 비어 있는 이름 저장을 막았다.
- 일반·Google 로그인 시 RTDB 프로필의 `name`이 없으면 Firebase 표시 이름, 이메일 앞부분 순서로 보완해 저장한다. Google 신규 계정도 같은 이름을 RTDB와 Firebase 프로필에 기록한다.
- 게시글·댓글 좋아요 알림은 기존 사용자 프로필의 이름·닉네임이 없더라도 이메일 앞부분을 표시 이름으로 사용해 `다른 사용자` 기본 문구가 나오지 않도록 했다.
- 가입·로그인 화면에서 구분선과 `OR` 문구를 제거하고, 일반 인증과 Google 인증 버튼을 각각 전체 너비 한 줄로 다시 배치했다.
