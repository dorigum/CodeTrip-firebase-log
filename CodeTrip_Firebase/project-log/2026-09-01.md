# 2026-09-01 작업 로그

## 1. Google OAuth 로그인·회원가입 도입 및 Firebase 설정 검증

### 작업 배경

기존 이메일·비밀번호 로그인 외에 Google 계정으로 가입과 로그인을 제공하도록 Firebase Authentication 기반 OAuth 흐름을 추가했습니다. 구현 후 Firebase Console과 Google Cloud Console 설정 과정에서 `deleted_client`, `redirect_uri_mismatch`, OAuth 직후 Realtime Database 권한 오류를 순차적으로 확인했습니다.

### 구현 내용

- `src/api/authApi.js`에 `GoogleAuthProvider`, `signInWithPopup` 기반 `loginWithGoogle()`을 추가했습니다.
- Google 로그인 최초 성공 시 `users/{uid}`에 이메일, 표시명, 프로필 이미지, 관심 지역, 생성·수정 시각, `authProvider: 'google'`을 저장합니다.
- 기존 사용자 프로필은 사용자 관리 필드를 덮어쓰지 않고 provider 정보만 보완합니다.
- 로그인과 회원가입 화면에 Google 버튼을 추가하고, 공식 4색 SVG 로고를 적용했습니다.
- 기존 2시간 세션, 로그아웃, 로그인 전 탐색 상태 보존 흐름을 사용합니다. Firebase ID 토큰은 Firebase SDK가 관리하며 앱에서 Web Storage에 별도 저장하지 않습니다.

### Firebase 및 Google Cloud 설정 확인

- Firebase 프로젝트 `newagent-9c2a8`의 Authentication에서 Google Provider를 사용 설정하고 지원 이메일을 지정했습니다.
- Google Cloud의 웹 OAuth 클라이언트에 로컬 원본 `http://localhost:5173`, `http://localhost:5180`과 Hosting 원본 `https://dorigum-codetrip.web.app`을 등록했습니다.
- 승인된 리디렉션 URI `https://newagent-9c2a8.firebaseapp.com/__/auth/handler`를 등록했습니다.
- Firebase Google Provider의 웹 SDK Client ID/Secret이 새 OAuth 웹 클라이언트와 일치하도록 확인했습니다.

### 장애 대응

- `401: deleted_client`: Firebase Google Provider가 삭제된 OAuth 클라이언트를 참조한 문제로, 새 웹 OAuth 클라이언트를 생성하고 Provider 웹 SDK 구성에 연결해 해결했습니다.
- `400: redirect_uri_mismatch`: OAuth 클라이언트에 Firebase 기본 handler URI를 저장하지 않아 발생했으며, 승인된 리디렉션 URI 등록·저장으로 해결했습니다.
- OAuth 인증 뒤 Realtime Database의 사용자 프로필 읽기에서 일시적으로 `PERMISSION_DENIED`가 발생할 수 있어, ID 토큰 확보 후 권한 오류일 때만 강제 갱신하여 한 번 재시도하도록 보완했습니다.

### 검증 결과

- Firebase Authentication 사용자 목록에서 Google 제공업체 계정 생성 확인
- Realtime Database `users/{uid}` 본인 인증 규칙 확인
- 로컬 환경 Google 로그인·회원가입 성공 확인
- `npm run lint` 오류 없음(기존 경고 11건 유지)
- `npm run build` 성공(기존 번들 크기 경고 유지)

## 2. Google 가입 후 회원가입 화면에 남는 라우팅 오류 보정

### 문제

Google 가입은 성공해 Header가 인증 상태로 바뀌지만, 회원가입 화면(`/signup`)이 그대로 남는 현상을 확인했습니다.

### 처리

- `src/pages/SignUp.jsx`에서 Google 가입 성공 후 `navigate('/', { replace: true })`로 히스토리를 대체하며 홈으로 이동하도록 정리했습니다.
- 이미 인증된 사용자가 `/signup`에 진입하거나 OAuth 처리 중 인증 상태가 먼저 반영되는 경우에도 홈으로 이동하도록 `isLoggedIn` 감시 리디렉션을 추가했습니다.

### 확인 기준

- Google 가입·로그인 성공 시 홈(`/`)으로 이동합니다.
- 브라우저 뒤로가기를 해도 가입 화면으로 되돌아가지 않습니다.
- 인증된 사용자가 직접 `/signup` 주소에 접근해도 홈으로 이동합니다.

## 3. PR #30 CodeRabbit 표시명 개인정보 노출 피드백 반영

### 검토 결과

CodeRabbit은 Google 계정에 `displayName`이 없고 Realtime Database 프로필이 아직 비어 있는 최초 로그인에서 `userPayload()`가 이메일을 이름 fallback으로 반환한다고 지적했습니다. 이 값은 로그인·회원가입 직후 Header와 사용자 상태에 전달되므로, 이름 영역에 이메일이 노출될 수 있어 유효한 피드백으로 판단했습니다.

### 수정 내용

- `src/api/authApi.js`의 사용자 표시명 fallback을 이메일 대신 `CodeTrip 사용자`로 변경했습니다.
- 저장된 `profile.name`과 Google `displayName`이 있는 경우의 기존 우선순위는 유지했습니다.
- 초기 검토에서 확인된 `trip_token` localStorage 경고는 후속 CodeRabbit 피드백에서 OAuth 흐름과 함께 즉시 개선 대상으로 확정되어, 아래 보안 보정 섹션에서 반영했습니다.

### 확인 기준

- 표시명이 없는 Google 계정의 최초 로그인에서도 이름 영역에 이메일이 노출되지 않습니다.
- 저장된 사용자 이름 또는 Google 표시명이 있으면 기존 값이 표시됩니다.

## 4. Google 기존 계정 가입 안내와 게시판·댓글 좋아요 권한 보정

### 문제

- 이미 Google OAuth로 생성된 계정이 회원가입 화면에서 다시 Google 가입을 누르면 로그인 상태가 되거나 일반 오류로만 보여, 사용자가 가입 불가 사유를 알기 어려웠습니다.
- Google OAuth 사용자가 게시글·댓글 좋아요를 누른 뒤 UI가 되돌아가거나 누적되지 않는 현상이 확인됐습니다. 댓글과 여행지 댓글 Rules에는 본인 UID가 아닌 사용자의 `likeUserIds` 하위 키를 쓸 수 있는 예외가 없었습니다.

### 수정 내용

- `getAdditionalUserInfo()`의 `isNewUser`로 Google 인증 결과가 신규 가입인지 구분합니다.
- 회원가입 화면에서 기존 Google 계정이면 인증 상태를 정리하고 `이미 Google 계정으로 가입되어 있습니다. 로그인 화면에서 Google 로그인을 이용해 주세요.` 안내를 표시합니다.
- Google 가입 처리 중 Auth listener가 먼저 인증 상태를 반영하더라도 기존 계정 안내 전에 홈으로 이동하지 않도록 가입 처리 상태를 분리했습니다.
- Realtime Database Rules에 `boardComments/{commentId}/likeUserIds/{uid}`와 `travelComments/{commentId}/likeUserIds/{uid}` 쓰기 권한을 추가했습니다. 게시글 좋아요는 기존 `boardPosts/{postId}/likeUserIds/{uid}` 규칙을 그대로 사용합니다.

### 배포 및 확인 기준

- `database.rules.json` 변경은 `firebase deploy --only database`로 Realtime Database에 배포해야 합니다.
- 기존 Google 계정으로 가입을 시도하면 안내가 표시되고, 로그인 화면의 Google 로그인으로는 정상 진입해야 합니다.
- Google OAuth 계정으로 타인의 게시글, 게시글 댓글, 여행지 댓글 좋아요를 각각 추가·새로고침·취소해도 수치와 상태가 유지되어야 합니다.

## 5. PR #30 CodeRabbit 좋아요·토큰·실패 정리 피드백 반영

### 검토 및 수정 내용

- 좋아요 트랜잭션이 `likeUserIds` 전체 부모를 갱신하면 댓글 작성자 전용 상위 Rules에 의해 비작성자 좋아요가 거부될 수 있어, 게시글·게시글 댓글·여행지 댓글 모두 `likeUserIds/{현재 UID}` 단일 Boolean 경로에서만 트랜잭션하도록 변경했습니다.
- 토큰 강제 갱신 재시도 후 오래된 ID 토큰을 반환·저장할 수 있다는 피드백은, 앱이 ID 토큰을 반환값·localStorage에 보관하지 않도록 바꿔 제거했습니다. Firebase SDK의 `browserSessionPersistence`가 인증 상태와 토큰 갱신을 관리합니다.
- Google 가입 처리 중 프로필 생성·조회가 실패하면 `cancelLogin()`을 호출해 Firebase Auth, 사용자 상태, 만료 상태를 정리하도록 보완했습니다.

### 확인 기준

- 일반 사용자와 Google OAuth 사용자가 타인의 게시글·게시글 댓글·여행지 댓글 좋아요를 추가·취소할 수 있어야 합니다.
- 좋아요는 해당 사용자 UID 키 하나만 변경하며, 다른 사용자의 좋아요 키를 변경할 수 없어야 합니다.
- Google 가입 실패 뒤 인증 Header나 잔여 로그인 상태가 남지 않아야 합니다.
- 앱 코드의 `trip_token` Web Storage 쓰기가 없어야 합니다.

## 6. 신규 Google 계정 최초 프로필 생성 시 Database 권한 지연 보정

### 문제

기존 Google 계정은 정상 로그인되지만, 다른 Google 계정으로 최초 회원가입을 시도하면 Firebase Authentication 성공 뒤 `users/{uid}` 프로필 조회에서 `PERMISSION_DENIED`가 발생했습니다. 기존 계정은 이미 Database 프로필이 있어 이 구간을 빠르게 통과하지만, 신규 계정은 OAuth 직후 Realtime Database 연결이 인증 토큰을 반영하기 전에 첫 요청을 보낼 수 있습니다.

### 처리

- OAuth 프로필 조회의 권한 오류 재시도를 최대 3회로 제한했습니다.
- 각 재시도 전에 Firebase ID 토큰을 강제 갱신하고, Realtime Database 연결이 새 토큰을 적용할 시간을 짧게 둡니다.
- 권한 오류 외 예외는 즉시 반환하고, 마지막 재시도까지 실패하면 기존 오류 처리를 유지합니다.

### 확인 기준

- 기존 Google 계정 로그인과 새로운 Google 계정 최초 가입이 모두 정상적으로 `users/{uid}` 프로필을 생성해야 합니다.
- 실제 Rules 오류는 재시도 횟수 이후 사용자에게 오류로 안내되어야 합니다.

## 7. 신규 Google 계정 프로필 쓰기 권한 지연 재시도 확대

### 문제

프로필 조회 재시도만 적용한 뒤에도 신규 Google 계정 가입이 실패했습니다. 신규 계정만 실행하는 `users/{uid}` 프로필 생성 쓰기(`set`)도 OAuth 직후에는 Realtime Database 인증 토큰 반영 지연으로 권한 거부될 수 있으나, 기존 구현은 이 쓰기를 즉시 실패 처리했습니다.

### 처리

- OAuth 후 Database 작업을 공통으로 실행하는 제한 재시도 함수를 만들었습니다.
- 프로필 조회와 신규 프로필 생성 쓰기 모두 권한 오류일 때만 ID 토큰 갱신·짧은 대기 후 최대 3회 재시도합니다.
- 기존 프로필의 `authProvider` 보정은 정상 로그인 이후의 일반 업데이트이므로 기존 흐름을 유지합니다.

### 확인 기준

- 다른 Google 계정으로 최초 가입하면 `users/{uid}` 프로필이 생성되고 가입이 완료되어야 합니다.
- 기존 Google 계정 로그인과 기존 계정 가입 안내 흐름은 유지되어야 합니다.

## 8. Google 회원가입 중 인증 리스너의 즉시 로그아웃 방지

### 문제

새 Google 계정 가입에서 `signInWithPopup()`이 성공해도 회원가입 화면은 로그인 시작 상태를 설정하지 않았습니다. 따라서 `onAuthStateChanged` 리스너가 세션 만료 상태로 판단해 방금 로그인한 Firebase 사용자를 즉시 로그아웃했고, 이어지는 `users/{uid}` Database 요청이 비인증 상태가 되어 `PERMISSION_DENIED`가 발생했습니다.

### 처리

- Google 회원가입을 시작하기 직전에 `prepareLogin()`을 호출해 2시간 세션 만료 시각과 로그인 진행 상태를 먼저 설정합니다.
- 인증 리스너가 OAuth 팝업 결과를 처리하는 동안 사용자를 로그아웃하지 않으며, 성공 시 기존 `login()` 호출이 진행 상태를 해제합니다.
- 기존 계정·실패 경로는 이미 사용 중인 `cancelLogin()`으로 인증 상태를 정리합니다.

### 확인 기준

- 새로운 Google 계정의 첫 가입에서 프로필이 생성되고 홈으로 이동해야 합니다.
- 기존 Google 계정으로 가입을 시도하면 기존 계정 안내가 표시되고 세션이 정리되어야 합니다.

## 9. 기존 Google 계정 회원가입 시 불필요한 프로필 조회 제거

### 문제

이미 가입된 Google 계정으로 회원가입을 시도하면 Firebase Auth의 `isNewUser`는 `false`였지만, 기존 구현은 이 값을 확인한 뒤에도 Realtime Database 프로필 조회를 먼저 수행했습니다. 회원가입 화면은 기존 계정 안내만 필요하므로 이 조회가 권한 오류가 나면 안내 대신 일반 인증 오류가 표시됐습니다.

### 처리

- `loginWithGoogle()`에 기존 계정의 프로필 조회를 건너뛸 수 있는 선택 옵션을 추가했습니다.
- 회원가입 화면은 이 옵션을 사용해 `isNewUser === false`인 경우 Firebase Auth 사용자 정보만 반환받고 즉시 기존 계정 안내·세션 정리 흐름으로 이동합니다.
- 로그인 화면은 기존처럼 Database 프로필을 조회해 사용자 정보를 복원합니다.

### 확인 기준

- 기존 Google 계정으로 회원가입을 시도하면 일반 인증 오류 없이 기존 계정 안내가 표시되어야 합니다.
- 신규 Google 계정 가입과 로그인 화면의 Google 로그인은 기존 동작을 유지해야 합니다.

## 10. 기존 Google 계정 재가입 중 인증 상태 경쟁 방지

### 문제

기존 Google 계정 재가입을 감지한 뒤 `cancelLogin()`으로 로그아웃해도, 먼저 시작된 인증 리스너의 비동기 프로필 조회가 늦게 끝나면서 오래된 로그인 결과가 상태를 다시 덮어썼습니다. 회원가입 화면은 잠시 로그인됐다가 로그아웃된 홈으로 이동했고, Google 계정 선택 창도 현재 세션 계정을 자동 사용해 표시되지 않을 수 있었습니다.

### 처리

- 인증 리스너 이벤트에 버전 번호를 부여하고, 로그아웃·취소·세션 만료 뒤 완료된 이전 비동기 조회 결과는 상태에 반영하지 않도록 했습니다.
- Google OAuth 제공업체에 `prompt=select_account`를 지정해 로그인·회원가입 시 계정 선택 창을 항상 표시합니다.

### 확인 기준

- 기존 Google 계정으로 회원가입을 시도하면 계정 선택 후 기존 계정 안내만 표시되고 홈으로 이동하지 않아야 합니다.
- 취소·로그아웃 후 늦게 완료된 인증 조회가 사용자 상태를 되살리지 않아야 합니다.
