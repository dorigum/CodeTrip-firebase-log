# 2026-08-22 작업 로그

> 이 문서는 2026-08-22에 `main` 반영 내역, PR #27 피드백 대응, 로컬 수정 커밋을 기준으로 정리했습니다.

## 1. 작업 개요

공모전 제출 전 최종 검증 과정에서 비회원 탐색 흐름, 로그인 복귀 경로, 탐색 페이지 상태 복원, 로그아웃 시 보호 라우트 안내 모달 표시 문제를 점검하고 보완했습니다. 사용자가 여행지 탐색 중 위시리스트 저장을 시도하거나 로그인·로그아웃을 반복해도 현재 맥락이 불필요하게 깨지지 않도록 인증 경계 UX를 안정화했습니다.

## 2. PR #27 반영 내역

PR #27에서는 비회원 사용자가 여행지 탐색 페이지에서 위시리스트 버튼을 눌렀을 때 로그인 안내를 제공하고, 로그인 후 원래 머물던 탐색 맥락으로 돌아오도록 흐름을 정리했습니다.

- `src/pages/Explore.jsx`
  - 비회원이 여행지 카드의 좋아요 버튼을 클릭하면 위시리스트 저장은 로그인한 사용자만 가능하다는 안내 모달을 표시하도록 했습니다.
  - 로그인 안내 모달에서 로그인으로 이동할 때 현재 탐색 경로와 query string을 `codetrip:return_after_login`에 저장하도록 했습니다.
  - 로그인 후 탐색 페이지로 돌아올 때 이전 페이지 번호, 검색어, 필터 상태가 필요한 경우에만 유지되도록 처리했습니다.
  - 다른 메뉴에서 탐색 페이지로 새로 진입하는 경우에는 이전 페이지가 고정되지 않고 1페이지 기준으로 초기화되도록 조정했습니다.
  - `keyword` 삭제와 페이지 초기화를 하나의 스토어 액션으로 묶어 이전 검색어 기준 요청이 뒤늦게 결과를 덮어쓰는 위험을 줄였습니다.

- `src/store/useExploreStore.js`
  - 탐색 검색어 초기화와 페이지 초기화를 원자적으로 처리하는 액션을 추가했습니다.
  - 탐색 페이지 복귀 시 유지해야 하는 상태와 새 진입 시 초기화해야 하는 상태를 분리했습니다.

- `src/pages/Login.jsx`
  - 로그인 성공 후 항상 홈으로 이동하지 않고, `location.state.from` 또는 `sessionStorage`에 저장된 복귀 경로가 있으면 해당 경로로 돌아가도록 했습니다.
  - 로그인 성공 후 사용한 복귀 경로는 제거해 다음 일반 로그인에 영향을 주지 않도록 했습니다.

- `src/components/ProtectedRoute.jsx`, `src/components/Layout/Header.jsx`
  - 보호 라우트 접근 시 로그인 후 복귀할 경로를 보존하도록 했습니다.
  - 헤더 로그인 버튼도 현재 경로를 기준으로 복귀 경로를 전달하도록 정리했습니다.

## 3. CodeRabbit 피드백 대응

PR #27 진행 중 CodeRabbit 피드백을 반영해 다음 항목을 보정했습니다.

- 로그인 복귀 경로 저장 시 불필요한 상태 누수를 방지했습니다.
- 탐색 페이지에서 검색어 삭제와 페이지 초기화가 서로 다른 요청으로 실행되어 결과 경합이 발생할 수 있는 구조를 정리했습니다.
- 다른 페이지에서 탐색으로 새로 진입하는 경우와, 로그인 후 기존 탐색으로 복귀하는 경우를 구분했습니다.
- 탐색 페이지 스크롤 복원 조건을 정리해 복귀 시에는 기존 위치를 유지하고 새 진입 시에는 상단에서 시작하도록 했습니다.

## 4. 로그아웃 보호 라우트 모달 깜빡임 수정

로그인한 사용자만 접근 가능한 페이지에서 로그아웃할 때, 홈으로 이동하기 직전 보호 라우트가 순간적으로 비로그인 상태를 감지해 로그인 안내 모달을 표시하는 문제가 있었습니다.

- `src/components/Layout/Header.jsx`
  - 로그아웃 확정 시 `codetrip:logout_redirecting` 플래그를 `sessionStorage`에 기록하도록 했습니다.
  - 로그아웃 후 홈 이동은 `navigate('/', { replace: true })`로 처리해 보호 페이지 히스토리가 남지 않도록 했습니다.

- `src/components/Layout/SideBar.jsx`
  - 사이드바 로그아웃 흐름에도 동일한 `codetrip:logout_redirecting` 플래그를 적용했습니다.
  - 데스크톱 사이드바와 모바일 하단 네비게이션의 로그아웃 경로가 같은 방식으로 동작하도록 맞췄습니다.

- `src/components/ProtectedRoute.jsx`
  - 명시적인 로그아웃 리다이렉트 중이면 로그인 안내 모달을 렌더링하지 않도록 했습니다.
  - 로그아웃 리다이렉트 플래그를 감지하면 플래그를 제거하고 홈으로 조용히 이동하도록 했습니다.

## 8. 트러블슈팅

### 8.1 로그아웃 시 보호 라우트 로그인 안내 모달이 순간적으로 표시되는 문제

- **현상**: 로그인한 사용자만 접근 가능한 페이지에서 로그아웃하면 홈으로 이동하기 전 `AI 여행 코스 접근 제한` 또는 회원 전용 페이지 안내 모달이 순간적으로 표시될 수 있었습니다.
- **원인**: 로그아웃 확정 시 `logout()`이 먼저 실행되어 인증 상태가 `false`로 바뀌었지만, 라우터가 아직 홈으로 이동하기 전이라 현재 보호 페이지의 `ProtectedRoute`가 비로그인 접근으로 판단했습니다.
- **처리**:
  - 로그아웃 확정 시 `codetrip:logout_redirecting` 플래그를 `sessionStorage`에 저장했습니다.
  - `ProtectedRoute`는 해당 플래그가 있으면 로그인 안내 모달을 렌더링하지 않고 홈으로 이동하도록 했습니다.
  - 홈 이동은 `replace: true`를 사용해 로그아웃 후 뒤로가기 시 보호 페이지가 남지 않도록 했습니다.
- **확인**:
  - `npm run lint`를 통과했습니다.
  - `npm run build`를 통과했습니다.
  - 변경 범위가 인증 경계 UI 파일 3개로 제한된 것을 확인했습니다.
- **운영 메모**:
  - 이 플래그는 명시적인 로그아웃 리다이렉트에만 사용합니다.
  - 일반적인 비로그인 보호 페이지 접근에서는 기존처럼 로그인 안내 모달을 표시합니다.
