## 2. 같은 contentId 장소 삭제 시 다른 폴더 카드까지 삭제될 수 있는 문제

- **발생일**: 2026-07-25
- **영향 범위**: 마이페이지 위시리스트 카드 삭제, AI 코스 폴더별 저장 장소
- **요약**: 같은 관광공사 장소가 여러 폴더에 저장된 상태에서 한 폴더의 카드만 삭제하려고 해도, `contentId` 기준 전역 삭제로 인해 다른 폴더의 동일 장소 카드까지 삭제될 수 있는 위험이 있었습니다.

### 원인

AI 코스 저장 로직은 같은 관광공사 `contentId`라도 폴더가 다르면 별도 위시리스트 record로 저장하도록 변경되었습니다.

하지만 삭제 로직은 여전히 `contentId` 기준으로 동작하고 있었습니다.

```text
문제 기준:
contentId가 같은 모든 wishlist record 삭제
```

이 구조에서는 같은 장소가 A 폴더와 B 폴더에 모두 저장되어 있을 때, A 폴더에서 삭제한 작업이 B 폴더의 카드까지 제거할 수 있습니다.

### 해결

마이페이지 카드 삭제는 Firebase wishlist record의 고유 `id` 기준으로 처리하도록 변경했습니다.

```text
변경 기준:
wishlist item id가 일치하는 단일 record만 삭제
```

### 검증 포인트

1. 같은 장소가 여러 폴더에 저장된 상태를 준비
2. 한 폴더에서 해당 장소 카드 1개 삭제
3. 다른 폴더의 동일 장소 카드가 유지되는지 확인
4. Realtime Database에서 삭제된 record가 하나인지 확인

## 3. Gemini 응답 본문 소비 지연 시 생성 상태가 오래 유지될 수 있는 문제

- **발생일**: 2026-07-25
- **영향 범위**: AI 여행 코스 생성, Gemini API 응답 처리
- **요약**: Gemini API 요청 자체에는 timeout이 있었지만, 응답 본문을 `response.json()` 또는 `response.text()`로 읽는 과정에는 별도 timeout이 없어 응답 본문 소비가 지연될 경우 생성 상태가 오래 유지될 수 있었습니다.

### 원인

기존 timeout은 `fetch()` 호출에만 적용되었습니다. 응답 헤더가 반환된 이후 본문 파싱이 지연되는 경우에는 별도 제한 시간이 없어 사용자가 계속 생성 중 상태를 보게 될 수 있었습니다.

### 해결

Gemini 응답 본문 소비에도 45초 timeout을 적용했습니다.

- 정상 응답: `response.json()` timeout
- 오류 응답: `response.json()` 및 `response.text()` timeout
- timeout 발생 시 사용자 친화 오류 메시지 반환

### 기대 효과

- Gemini 응답이 비정상적으로 지연되어도 UI가 무기한 대기하지 않음
- 네트워크 불안정 또는 API 지연 상황에서 사용자에게 명확한 재시도 안내 가능
