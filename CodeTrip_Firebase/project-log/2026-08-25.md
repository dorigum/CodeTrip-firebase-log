# 2026-08-25 작업 로그

> 이 문서는 PR #28 `feature/trip-date-planning` 브랜치에서 AI 플래너 폴더 주소 보강 경합 처리, Info 화면 버전 표기, 모바일 하단 내비게이션 보강, 개발용 캐시 패널 위치 조정 작업을 기록합니다.

## 1. 작업 개요

AI 여행 일정 날짜 기능을 추가한 이후, 폴더 기반 생성 흐름에서 비동기 주소 보강이 끝나기 전에 사용자가 생성 버튼을 누르거나 입력값을 변경할 수 있는 경로를 보완했습니다. 이번 작업의 목적은 폴더 선택, 장소 주소 보강, 지역명 자동 반영, 생성 요청이 서로 충돌하지 않도록 AI Planner의 busy-state와 최신성 검증을 더 명확하게 만드는 것입니다.

또한 제출 직전 MVP 후보 상태를 더 정확하게 드러내기 위해 Info 화면 버전 표기를 `MVP 0.9.0-rc`로 조정했습니다. 모바일 사용성 측면에서는 하단 내비게이션에 `Info` 진입점을 추가하고, `My Page`는 사용자 관점에서 가장 찾기 쉬운 오른쪽 끝에 유지하도록 정리했습니다. `Info` 메뉴는 데스크톱과 동일하게 외부 참고 링크와 About 화면으로 이어지는 하위 메뉴를 모바일 팝업으로 제공합니다.

## 2. AI Planner 폴더 주소 보강 상태 처리

폴더 기반 AI 일정 생성 모드에서는 선택한 폴더 안의 여행지 주소가 부족한 경우 `hydratePlaceAddresses()`가 비동기로 주소를 보강합니다. 이 작업이 진행 중일 때 생성 버튼이 활성화되어 있으면, 화면에는 아직 보강 중인 데이터가 표시되고 있는데 생성 요청은 이전 상태를 기준으로 실행될 수 있습니다.

이를 보완하기 위해 `folderHydrating` 상태를 추가했습니다.

- 폴더 장소 주소 보강 시작 시 `folderHydrating`을 `true`로 설정합니다.
- `plannerBusy` 조건에 `generating`, `saving`, `folderHydrating`을 함께 포함합니다.
- 생성 또는 저장 중이 아닌 경우에만 폴더 변경을 허용하도록 `plannerActionBusy`를 분리했습니다.
- 주소 보강 결과는 `folderSelectionRequestRef`와 `plannerRevisionRef`가 모두 최신일 때만 화면 상태에 반영합니다.
- 주소 보강 실패 시에는 기존 폴더 장소 목록을 fallback으로 사용하고, 사용자가 생성 흐름을 이어갈 수 있도록 했습니다.

이 변경으로 폴더 선택 직후 주소 보강이 진행되는 짧은 구간에서 중복 생성, 오래된 폴더 결과 반영, 지역명 덮어쓰기 가능성을 줄였습니다.

## 3. Info 화면 버전과 서비스명 표기 정리

Info 화면의 시스템 표기는 최종 정식 배포가 아닌 공모전 제출 전 MVP 후보 상태를 나타내도록 `system.info — MVP 0.9.0-rc`로 조정했습니다.

서비스명도 화면 내 표기를 `CodeTrip`으로 맞췄습니다. 이는 README와 기능설명서, 제출 문서에서 사용하는 서비스명과 UI 표기를 일치시키기 위한 정리입니다.

## 4. 모바일 하단 내비게이션 Info 진입점 추가

모바일 웹 화면에서는 하단 탭 영역에 `Info` 메뉴가 노출되지 않아 정보 화면 접근성이 떨어지는 문제가 있었습니다. 사용자 관점에서는 개인 계정과 저장 데이터를 확인하는 `My Page`가 가장 오른쪽에 고정되는 편이 더 자연스럽기 때문에, 모바일 하단 내비게이션 순서를 아래처럼 정리했습니다.

1. Home
2. Explore
3. Festivals
4. AI Planner
5. Board
6. Info
7. My Page

이 구조는 `My Page`를 오른쪽 끝에 유지하면서도, 서비스 정보와 시스템 안내 화면에 모바일에서도 접근할 수 있게 합니다.

`Info` 탭은 단순히 `/info`로 바로 이동하는 링크가 아니라, `My Page`와 같은 방식의 모바일 하위 메뉴 팝업을 띄우도록 수정했습니다. 모바일 팝업에서는 공공 와이파이, 세이프스테이, 교통 예약 링크와 About CodeTrip 화면으로 이동할 수 있습니다. 다른 하단 메뉴를 누르면 `Info` 팝업과 `My Page` 팝업이 서로 닫히도록 처리했습니다.

## 5. Info 전용 개발용 API 캐시 패널 위치 조정

개발 모드에서 표시되는 `API_CACHE.LOG` 패널이 화면 폭을 줄였을 때 왼쪽 사이드바 또는 메뉴 항목과 겹치는 문제가 있었습니다. 이 패널은 사용자 기능이 아니라 개발·검증용 보조 UI이므로, Info 화면에서만 표시되도록 제한하고 주요 내비게이션과 충돌하지 않도록 오른쪽 하단 기준으로 위치를 조정했습니다.

이 변경은 API 캐시 상태를 확인하는 기능 자체를 바꾸지 않고, 일반 탐색·축제·AI Planner 화면의 콘텐츠를 가리지 않도록 표시 범위를 줄이는 UI 안정화 작업입니다.
