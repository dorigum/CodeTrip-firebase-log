# 2026-08-16 작업 로그

> 이 문서는 2026-08-16에 기존 커밋, Firebase 배포 결과, 검증 문서를 기준으로 정리했습니다.

## 1. 작업 개요

Gemini API 호출 구조를 클라이언트 직접 호출에서 Firebase Callable Function 프록시 구조로 전환했습니다. 공개 Hosting 환경에서 Gemini API 키가 브라우저 번들에 포함될 수 있는 위험을 줄이고, 서버 측 Secret으로 키를 관리하는 방향으로 보안 구조를 개선했습니다.

## 2. 구현 변경

- `functions/index.js`
  - `generateTripPlan` Callable Function을 추가했습니다.
  - Firebase Auth 인증 여부를 서버에서 확인하도록 했습니다.
  - 입력 크기, 기간, 선호 장소 수 등 기본 검증을 Functions 내부에서 수행하도록 했습니다.
  - Gemini 요청과 JSON 파싱, 응답 정규화를 서버 측으로 이동했습니다.
  - 로그에는 `uid`, `durationDays`, `preferredPlaces` 같은 최소 정보만 남기고 요청 원문, 응답 원문, API 키는 기록하지 않도록 했습니다.

- `src/api/geminiApi.js`
  - 브라우저에서 Gemini API를 직접 호출하던 구조를 제거했습니다.
  - `httpsCallable(firebaseFunctions, 'generateTripPlan')` 호출 구조로 전환했습니다.
  - 클라이언트는 사용자 입력 전달과 사용자용 오류 메시지 처리만 담당하도록 역할을 축소했습니다.

- `src/firebase.js`
  - `asia-northeast3` 리전의 Firebase Functions 인스턴스를 명시적으로 export했습니다.

- `firebase.json`, `functions/package.json`
  - Functions source와 Node.js 22 런타임을 반영했습니다.

## 3. 배포 및 Secret 관리

- Firebase 프로젝트 `newagent-9c2a8`에 `GEMINI_API_KEY` Functions Secret을 등록했습니다.
- `generateTripPlan` v2 Callable Function을 `asia-northeast3` 리전에 배포했습니다.
- Firebase Hosting 대상 `codetrip`에 최신 프론트 빌드를 배포했습니다.
- Artifact Registry cleanup policy를 1일 기준으로 설정했습니다.
- 기존 Gemini 키는 신규 키로 교체한 뒤, 기존 `Gemini API Key_temp`를 AI Studio에서 삭제했습니다.
